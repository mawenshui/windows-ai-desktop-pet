# 0.16.0－功能扩展计划

日期：2026-09-09。基线：0.15.0 已具备本地待办、结构化单项 AI 草稿、加密 AI 配置迁移和 GitHub 在线更新。本计划直接依据当前 `src/`、`tests/` 与设置/待办 schema 重新设计，不把历史计划中的候选描述当作已实现事实。

## 目标

0.16.0 聚焦每天都会用到的待办整理，不加入付费、账号、商城、云同步、广告或遥测。用户可以快速找出已逾期和未安排事项，明确勾选少量待办后生成当天时间块，核对每项安排再一次写入，并能撤销整批变更。

## 用户流程

1. 进入待办页，先用“已逾期”或“未安排”筛选判断当天压力。
2. 在“今日安排”卡片勾选 1～12 条待处理事项。
3. 选择“AI 安排今天”或“不访问网络的本地安排”。
4. 查看每项标题、开始/结束时间和简短理由；取消不想写入的单项。
5. 点击“确认应用所选”后才保存。列表显示计划时间块，截止时间同步为时间块结束。
6. 若结果不合适，可在本次运行中撤销最近一批；若待办在草稿后被编辑，应用或撤销会拒绝旧快照。

## 数据与安全边界

- `todos.json` 升级到 schema 4，新增可空 `plannedStartAt`；升级前保留 `.pre-v4.bak`。不新增账户、数据库或第三方依赖。
- AI 请求只包含用户当前明确勾选的事项，不读取或发送未勾选待办、已完成事项、搜索索引、文件路径、提醒历史或其他配置。
- AI 返回的 ID 必须与输入集合完全一致；缺失、重复、额外 ID、无时区绝对时间、跨日、过去时间、超长或重叠时间块全部拒绝。
- AI 和本地安排都只生成内存草稿。写入前可逐项排除；批量更新先全部校验，再原子替换文件并只触发一次变更通知。
- 不记录待办正文、AI 请求/响应或安排理由到日志。撤销记录只在内存保存，应用退出后清除。

## 验收条件

- TODAY-AC-01：已逾期、未安排、今天筛选在截止/提醒/计划时间组合下返回正确集合。
- TODAY-AC-02：只上传勾选项；1 条与 12 条通过，0 条和 13 条拒绝，未勾选正文不进入请求。
- TODAY-AC-03：结构化结果必须覆盖全部选中 ID，且时间块位于本地今天、晚于当前时间、使用当前偏移、互不重叠。
- TODAY-AC-04：本地安排不调用网络；今天剩余空间不足时不写入并给出减少事项提示。
- TODAY-AC-05：确认前文件不变；任一事项被并发修改时整批不写；成功后列表显示计划开始/结束，撤销整批恢复原快照。
- TODAY-AC-06：完整自动化、Release 构建、便携/安装/启动/卸载和 SHA-256 必须重新验证；真实鼠标键盘、签名和物理环境按实际报告 PASS、FAIL 或 SKIP。

## 本版不实施

- 自动替用户完成、删除、拆分或延期事项。
- 读取日历、邮件、聊天、文档正文或系统活动来推断计划。
- 后台静默重排、跨天自动迁移、团队协作、云同步与任何商业化能力。
- 用 AI 输出直接触发文件、程序、网络或系统操作。

0.16.0 功能实现与自动化已完成；候选资产仍须从干净提交构建。独立 UI/窗口性能因当前桌面无法置前而 FAIL，签名与多屏等物理项目仍待条件满足，因此本计划不等同于正式发布证明。后续再评估 0.17.x 的本地提醒冲突检查与通知可达性自检，不在本计划中预先声明实现。
