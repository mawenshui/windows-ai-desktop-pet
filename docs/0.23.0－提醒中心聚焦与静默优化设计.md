## 1. 目标与边界

本轮继续优化已有提醒中心，不新增页面、账号、云同步、遥测、外部资源、运行时依赖或通知数据字段。目标是让提醒记录增多后仍可快速定位待处理事项，在列表与目标动作之间保持清楚的单选关系，并把静默时段从“直接填写后尝试保存”提升为有草稿、有校验、有保存状态的可恢复表单。

版本选择 `MINOR`：新增向后兼容的提醒查找、筛选、排序、选中操作和静默预设能力。设置 schema 维持 5，待办 schema 维持 4，通知 schema 维持 1，快捷入口 schema 维持 1；查询、筛选、排序、选择、计数、校验提示和静默编辑基线均为进程内视图状态，不写入磁盘。

设计沿用 `.ui-craft/brief.md` 与 `.ui-craft/tokens.md`：桌宠仍是常驻主体，提醒中心保留在待办页原有渐进区域；继续使用奶油米白、柔和暖橙、原生 WPF 控件、非颜色状态、可见焦点和至少 36 DIP 的紧凑操作。签名细节是“提醒聚焦操作带”：列表只表达记录、状态和当前选择，完成、稍后与详情集中到列表下方，复用主页搜索结果与待办清单已经验证的心智模型。

| 12 | UX-230-12 | 状态表达 | 行内显示提醒类型、恢复来源和明确状态文字 | 排队、已提交、已处理、已取消和启动后恢复均不只依赖颜色 |
| 13 | UX-230-13 | 可访问性 | 为行、操作带、查找、筛选和目标按钮增加目标化名称/帮助 | 屏幕阅读器无需遍历整行即可理解目标、状态与快捷键；紧凑按钮不低于 36 DIP |
| 14 | UX-230-14 | 静默草稿 | 为启用、开始和结束建立可观察的编辑基线与未保存状态 | 只有真实差异才标记有修改；挂接中心与成功保存后推进基线 |
| 15 | UX-230-15 | 静默校验 | 增加 `HH:mm`、启用时起止不能相同的实时校验 | 无效时显示具体下一步并禁止保存；任一字段变化清理旧提交错误 |
| 16 | UX-230-16 | 静默预设 | 增加夜间、午休和关闭静默三个草稿快捷动作 | 只修改进程内草稿，不直接写入通知文件；仍需用户显式保存 |
| 17 | UX-230-17 | 保存反馈 | 保存按钮区分“保存静默设置”和“静默设置已保存” | 仅在中心已挂接、草稿有效且有修改时可执行；成功/失败均保留可见反馈 |
| 18 | UX-230-18 | 历史与状态 | 清理按钮显示可清数量并在无目标时禁用，提醒区使用独立 live region | 清理继续保留未处理提醒与待办；测试、清理、保存和目标动作反馈不拼接异常或敏感内容 |

顺序约束：先建立不落盘的数据投影，再加入查找/筛选/排序和空态；随后接入单选、选择恢复、摘要、统一操作与键盘路径；最后处理静默草稿、实时校验、预设、保存和历史反馈。每个阶段先补 ViewModel/合同测试再调整相应界面；任一阶段相关测试失败时不得把后续项目标记完成。

## 3. 状态与交互设计

### 3.1 查找、筛选与排序

提醒查找只作用于当前通知快照的标题。投影顺序固定为：读取一次快照并计算三类计数，应用所选筛选，再匹配标题，最后排序。筛选计数不随查询变化，避免输入一个无匹配词后所有分段同时变为零。默认“处理优先”先列出排队中与已提交记录并按计划时间排序，历史记录按入队时间倒序；“最近记录”统一按入队时间倒序。

空态遵循单一恢复动作：查询无匹配时只清空提醒查找；非待处理筛选为空时返回待处理；待处理为空但存在历史时查看历史；完全没有记录时由用户主动排队一次通道测试。空态动作不自动创建业务待办。

### 3.2 选择、操作与键盘

提醒列表使用原生单选 `ListBox`。刷新前保存通知 ID，刷新后只恢复仍在当前投影中的同一项。卡片行只展示标题、类型、时间、投递状态与恢复来源；完成、稍后和详情集中到列表下方的暖橙浅色操作带。

详情可打开仍存在的业务事项；完成与稍后只对可处理记录开放。稍后时长仍限定为 5、10、30、60 分钟。键盘行为只在提醒列表内生效：Enter/F2 打开详情，`Ctrl+Enter` 完成，`Ctrl+Shift+Enter` 使用当前时长稍后。提醒区内按 `Ctrl+F` 聚焦提醒查找；待办页其他区域继续聚焦待办查找。

### 3.3 静默设置

静默设置保留启用、开始和结束三个字段，但改为显式草稿。夜间预设写入 22:00～08:00，午休预设写入 12:00～13:00，关闭预设只停用静默；所有预设都只修改草稿。开始/结束始终要求 `HH:mm`，启用时两者不能相同。保存成功后推进基线，失败保留输入；字段变化清除旧提交错误并刷新按钮与 live region。

## 4. 测试计划

1. `TodoViewModelTests` 覆盖标题查找、三筛选计数、两排序、空态动作和查询不影响计数。
2. `TodoViewModelTests` 覆盖选择恢复/清除、选择摘要、详情/完成/稍后可用性与目标失效恢复。
3. `TodoViewModelTests` 覆盖静默草稿、三预设、实时校验、保存基线、清理计数和独立状态反馈。
4. XAML 合同测试覆盖原生单选、单一操作带、36 DIP、目标化 UIA、live region、查找/筛选/排序和静默提示。
5. WPF 生命周期或代码合同覆盖提醒列表快捷键、提醒区内 `Ctrl+F` 与待办其他区域的焦点分流。
6. 实现后运行两次 `scripts/test.ps1 -CI`，再运行独立 UI、系统、性能和打包/烟雾入口；签名及物理环境证据按实际结果记录 PASS、FAIL 或 SKIP。

## 5. 验收标准

| ID | 验收要求 |
| :--- | :--- |
| AC-UX-230-01 | 提醒查找只在本地匹配标题；清空后保留筛选与排序，查询不进入存储、日志或 AI |
| AC-UX-230-02 | 待处理、历史、全部计数来自同一快照；两种排序稳定且不更改通知数据 |
| AC-UX-230-03 | 无记录、筛选为空和查询无匹配分别给出唯一恢复动作，动作后用户能继续任务 |
| AC-UX-230-04 | 原生列表键盘移动可用；刷新只恢复仍可见的同一通知 ID，不自动选中其他记录 |
| AC-UX-230-05 | 统一操作带只对当前通知生效，详情/完成/稍后继续使用既有安全存储与通知处理语义 |
| AC-UX-230-06 | Enter/F2、`Ctrl+Enter`、`Ctrl+Shift+Enter` 只在提醒列表上下文生效；提醒区内 `Ctrl+F` 与待办查找正确分流 |
| AC-UX-230-07 | 类型、恢复来源、投递状态和操作目标均有文字与可访问名称，按钮命中区不低于 36 DIP |
| AC-UX-230-08 | 静默三字段准确跟踪未保存状态；预设只改草稿，成功保存后才写入通知文件并推进基线 |
| AC-UX-230-09 | 实时提示覆盖格式和相同时段；无效或无修改时不保存，失败保留输入且字段变化清理旧错误 |
| AC-UX-230-10 | 清理数量与实际可移除记录一致；清理保留所有未处理提醒与业务待办，所有反馈不暴露异常或敏感内容 |

## 6. 非目标与发布边界

- 不新增通知已读回执、系统通知操作按钮、批量完成、跨设备同步或进程外提醒服务。
- 不修改 `NotificationDocument`、`NotificationEntry`、待办或设置 schema，不迁移现有数据。
- 不把通知查询、筛选、排序、选择、静默草稿或状态反馈写入磁盘、日志、诊断、备份说明或 AI 上下文。
- 不以进程内 WPF 测试替代真实前台输入、多屏/缩放、休眠/时区、Explorer 重启或代码签名。
- 完整门禁未通过时只能作为候选，不创建稳定标签或 GitHub Release。
