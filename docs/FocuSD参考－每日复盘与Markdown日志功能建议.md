## 1. 结论

建议为当前项目增加一个“每日复盘”功能：用户在待办页记录当天的自由文本，应用自动汇总当天待办结果并按日期归档；用户需要时可把任意一天显式导出为 UTF-8 Markdown 文件。

它比 FocuSD 的剪贴板历史、媒体控制或 Agent 状态灯更适合当前项目：现有产品已经具备待办、今日安排、本地持久化、维护备份和离线优先边界，新增复盘只需沿这些能力向后延伸，不需要监听系统剪贴板、不需要接入新的外部服务，也不扩大 AI 数据范围。

本功能已按 `MINOR` 版本落入 0.24.0 候选工作区。本文同时保留调研依据、冻结后的需求边界和实施核对；候选实现不等于稳定发布。

## 2. 从 FocuSD 观察到的做法

FocuSD 把每日笔记和待办放在同一个 Notebook 交互中，并提供按日期回看和 Markdown 保存：

- README 将“待办与每日笔记”“跨天归档”和本地 `YYYY-MM-DD.md` 保存列为核心能力，参见[项目说明](https://github.com/zzliu93-debug/FocuSD/blob/c284eb14d0fb4a3f8707cb8d96fc698ccedcf9f3/README.md)。
- 归档模型把日期、待办快照、每日笔记和保存状态放在一起，参见[`TodoArchive`](https://github.com/zzliu93-debug/FocuSD/blob/c284eb14d0fb4a3f8707cb8d96fc698ccedcf9f3/src/App.tsx#L61-L67)。
- 待办复选项与自由文本被组合成一个 Markdown 文档，参见[Markdown 格式化逻辑](https://github.com/zzliu93-debug/FocuSD/blob/c284eb14d0fb4a3f8707cb8d96fc698ccedcf9f3/src/App.tsx#L848-L862)。
- 日期变化时保存前一天内容、归档并清空当日笔记，参见[跨日处理](https://github.com/zzliu93-debug/FocuSD/blob/c284eb14d0fb4a3f8707cb8d96fc698ccedcf9f3/src/App.tsx#L4200-L4247)；编辑后还会延迟写入 Markdown，参见[延迟保存](https://github.com/zzliu93-debug/FocuSD/blob/c284eb14d0fb4a3f8707cb8d96fc698ccedcf9f3/src/App.tsx#L4522-L4547)。
- 原生端按日期生成文件名并写盘，参见[`save_todo_markdown`](https://github.com/zzliu93-debug/FocuSD/blob/c284eb14d0fb4a3f8707cb8d96fc698ccedcf9f3/src-tauri/src/lib.rs#L408-L431)。

这些做法证明了“当天任务 + 当天记录 + 日期归档”是一条短且容易理解的工作流。不过不能直接复制其实现：调研时该仓库 README 明确写明尚未声明许可证，GitHub API 也未识别到许可证。因此本文只借鉴产品思想和公开可观察行为，不复制源码、文案、视觉资产或专有布局。

## 3. 面向当前项目的功能定义

### 3.1 用户价值

当前待办回答“接下来做什么”，每日复盘补足“今天实际发生了什么”。完成一天后，用户不必再到另一个应用整理工作记录；历史记录仍保存在本机，并可按需导出为普通 Markdown，便于长期保存或交给其他工具处理。

### 3.2 核心流程

1. 用户进入“待办”，在页内二级切换中选择“复盘”，不新增第五个主页面。
2. 页面展示当天自动摘要：已完成、仍待处理、已安排三个数量，以及相关事项的只读标题列表。
3. 用户在一个最多 4,000 字的“今日记录”文本框中输入内容；输入停止 500 ms 后自动保存到应用数据目录。
4. 用户可浏览以前日期。当天视图使用实时待办投影；日期跨越、系统恢复或下次启动发现日期变化时，为前一天固化一份只读事项快照。
5. 用户点击“导出 Markdown”后选择目标文件。应用默认建议 `YYYY-MM-DD.md`，仅在用户确认后写入；已有文件仍使用系统覆盖确认，不做后台静默覆盖。
6. 用户可以删除某日复盘；删除只移除复盘文本和历史快照，不修改、恢复或删除 `TodoStore` 中的事项。

### 3.3 建议需求编号

以下编号已写入 PRD 和 TEST_PLAN：

| ID | 优先级 | 候选需求 |
| :--- | :--- | :--- |
| JOURNAL-01 | P1 | 待办页提供“清单 / 复盘”二级切换，保持现有四页信息架构 |
| JOURNAL-02 | P1 | 当日记录本地自动保存，最多 4,000 字，保存失败保留草稿并明确下一步 |
| JOURNAL-03 | P1 | 摘要由现有待办数据本地计算，不发送网络、AI 或遥测 |

## 4. 产品边界与关键取舍

### 4.1 与当前待办模型的关系

FocuSD 会在跨日时复制未完成事项；当前项目不应照搬。现有 `TodoStore` 已经保存长期事项、重复规则、提醒队列、完成时间和 `plannedStartAt`，再复制会产生重复提醒、重复 ID 或并发覆盖风险。

本方案采用“实时投影 + 跨日只读快照”：

- 当天摘要从 `TodoStore` 计算，不创建新事项。
- 相关事项是本地日期等于目标日期的 `CompletedAt`、`PlannedStartAt`、`DueAt` 或 `ReminderAt` 记录。
- 跨日快照只保留显示所需字段：稳定 ID、标题、当日状态和相关时间；不复制备注、重复规则、提醒状态或通知历史。
- 待办后续被编辑或删除时，历史快照保持不变；复盘页面不能从快照反向修改待办。

### 4.2 保存与导出分离

应用内保存是可靠性路径，Markdown 是用户主动的数据出口，两者不能互相充当唯一副本：

- `journal.json` 使用现有原子写入、previous 备份和“损坏后阻止空内容覆盖”策略。
- 500 ms 防抖只合并写入；每次写入携带修订号，旧异步任务不能覆盖较新的文本。
- 切页、收起窗口或退出时尝试刷新未写入草稿；失败时显示“尚未保存”，并允许继续编辑或重试。
- Markdown 只通过系统文件选择器显式导出。这样无需新增默认文件夹、后台目录权限或设置 schema，也不会与用户手工修改的 Markdown 静默冲突。

### 4.3 Markdown 建议格式

```markdown
# 2026-09-14 每日复盘

## 当日概览

- 已完成：3
- 仍待处理：2
- 已安排：4

## 事项

- [x] 完成发布说明
- [ ] 跟进实机验证

## 今日记录

今天完成了候选包核对，实机签名验证仍待补充。
```

输出顺序稳定，设计冻结为 LF 换行和 UTF-8 无 BOM；标题中的换行和控制字符会规范化，正文内容按用户原文保留，仅统一换行。导出失败只显示稳定错误类别，不在日志中写完整目标路径或复盘正文。

## 5. 界面与可访问性建议

- “清单 / 复盘”使用页内可见单选，不使用仅图标或隐藏 Popup；初始仍进入“清单”，不改变现有主路径。
- 复盘页从上到下为日期导航、三项摘要、事项只读列表、今日记录、保存状态与“导出 Markdown”。
- 历史日期默认只读；点击“编辑记录”后只允许修改复盘文本，不允许编辑事项快照。
- `Ctrl+S` 立即刷新复盘草稿；`Esc` 先退出历史编辑或处理保存失败，再回到清单，最后才收起工具窗。
- 自动保存状态至少区分“正在保存 / 已保存 / 尚未保存 / 保存失败”，同时提供文字、可访问名称和 polite live region。
- 控件继续沿用当前奶油米白、暖橙、原生 WPF 控件、可见焦点和至少 36 DIP 的交互目标，不复刻 FocuSD 的灵动岛或 Notebook 视觉。

## 6. 技术落点

建议不增加第三方依赖：

| 层 | 建议改动 |
| :--- | :--- |
| Domain / Storage | 在 `AiPet.Todos` 增加 `DailyJournalEntry`、`DailyJournalSnapshotItem` 和 `DailyJournalStore`；独立保存 `journal.json` schema 1 |
| ViewModel | 增加 `TodoViewModel.Journal.cs`，负责日期投影、快照、修订号、防抖保存、删除和导出命令 |
| UI | 在 `PetToolWindow.xaml` 的待办页加入二级切换与复盘面板；保持既有 `Ctrl+Enter` 编辑器语义不变 |
| Maintenance | 增加 `DataModule.Journal`，纳入手动/每日备份、恢复预览、事务回滚、重置和卸载清理；不与搜索索引绑定 |
| Export | 通过可测试文件对话框适配器选择目标，使用临时文件 + 原子替换；UTF-8 无 BOM 或有 BOM 需在设计冻结时统一 |

建议数据结构：

```json
{
  "schemaVersion": 1,
  "entries": [
    {
      "date": "2026-09-14",
      "note": "今天的记录",
      "revision": 3,
      "updatedAt": "2026-09-14T21:30:00+08:00",
      "finalizedAt": null,
      "snapshot": []
    }
  ]
}
```

存储校验至少限制：日期格式与唯一性、每条正文 4,000 字、每日日志最多 256 个快照事项、单个标题 200 字、总文件 32 MiB、时间戳可解析、未知高版本 schema 拒绝写回。历史数据不自动过期；用户可以逐日删除或通过维护页整体清理。

## 7. 隐私、安全与许可

- 全功能默认离线，不调用 AI。即使用户已配置 AI Provider，复盘正文和事项快照也不得自动进入请求。
- 复盘属于个人数据：进入备份前需要在模块预览中明确显示；诊断只允许导出 schema、条目数和最后成功保存时间，不能导出正文、事项标题或完整文件路径。
- Markdown 导出目录不自动加入搜索授权范围；用户若需要正文搜索，仍须通过现有 SRCH-02 流程单独授权。
- 写文件前规范化目标并拒绝目录、设备路径、ADS 和重解析点绕过；错误信息不拼接原异常或完整路径。
- 不引入 FocuSD 源码或资产。若未来希望复用任何具体实现，必须先取得明确许可证或作者授权并完成第三方依赖/许可记录。
- Codex/Claude Code 状态灯、Hooks、状态文件、任务阶段和任何 Agent 监控均不在本功能范围。

## 9. 非目标

- 不做 Codex 或任何 AI Agent 状态指示。
- 不做云同步、账号、多人协作、遥测或在线发布。
- 不做 AI 自动总结、情绪分析或自动改写复盘。
- 不监听剪贴板，不控制系统媒体。
- 不在复盘页编辑、复制或自动顺延待办。
- 不做完整 Markdown 编辑器、富文本预览、附件或图片嵌入。
- 不默认向 Documents 写文件，不后台覆盖用户维护的 Markdown。

## 10. 建议实施顺序

1. 冻结 JOURNAL 与 AC 编号，更新 PRD、TECHNICAL_DESIGN 和 TEST_PLAN。
2. 实现独立 journal schema、原子存储、校验、损坏保护和修订竞争测试。
3. 实现当天投影与跨日快照，验证不影响 `TodoStore`、重复提醒和今日安排。
4. 接入待办页二级切换、历史浏览、自动保存状态、删除和可访问性。
5. 实现显式 Markdown 导出及安全路径适配器。
6. 接入维护备份/恢复/卸载，再执行完整自动化、候选打包和真实 Windows 验收。

上述顺序已用于 0.24.0 候选实现。完整自动化、候选打包和真实 Windows 门禁分别记录；在全部门禁通过前仍只称“候选功能”，不更新为稳定发布状态。
