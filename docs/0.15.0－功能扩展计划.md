# 0.15.0－功能扩展计划

日期：2026-09-08；依据当前 `src/`、`tests/`、配置 schema 和产品入口重新设计。本文只规划单机效率功能，不包含商业化方向。**“已实施”表示代码已有入口和自动化覆盖；“后续”表示尚未实现，不能当作当前能力。**

## 1. 当前基线与排序原则

0.14.0 已具备本地授权搜索、快捷入口、待办与提醒、多组 AI 配置、AI 待办草稿、全局快捷键和每日自动备份。0.15.0 先解决完整 AI 配置迁移，又补齐安装包已有但用户无法获知新版本的问题。

后续能力按以下顺序判断：

1. 先消除已有高频流程中的重复输入、丢失和恢复困难。
2. AI 只处理用户本次明确选择的数据，先显示输入范围和结构化草稿。
3. 所有待办、提醒、文件和配置变更仍由用户确认；失败不产生部分写入。
4. 手动功能始终可用，不让 AI、联网或某家供应商成为前置条件。
5. 不增加登录、云同步、遥测、团队、付费角色、商城、广告或订阅。

## 2. 0.15.0 实施范围

### EXT-11 加密完整 AI 配置包

状态：**0.15.0 已实施，等待完整发布门禁。**

设置页新增“导出完整配置”和“导入完整配置”。完整包使用 `.aipet-ai-config` 扩展名，包含：

| 内容 | 导出与导入规则 |
| :--- | :--- |
| 全部已保存配置 | 名称、供应商 ID、端点、模型、连接状态和上次验证时间全部迁移 |
| API Key | 从当前 Windows 账户凭据库读取，只进入加密载荷；导入后写入目标账户凭据库 |
| 当前配置 | 保存当前配置标识；导入成功后立即选择并加载对应配置，无需重新填写 Key |
| AI 激活设置 | 保留现有显式激活状态；完整包始终带有一个有效当前配置 |
| 自定义 Provider | 保存全部自定义预设及启用设置；不允许覆盖内置 Provider ID |
| 来源信息 | 保存包 schema、应用版本和 UTC 导出时间，用于预览与兼容判断 |

安全与事务规则：

- 用户必须设置至少 10 个字符的独立迁移口令并再次确认。口令不保存，遗失后不能恢复。
- 采用 PBKDF2-HMAC-SHA256（310,000 次）派生 256 位密钥，使用 AES-256-GCM 加密和完整性认证；外层 JSON 只包含格式、算法参数、盐、nonce、tag 和密文。
- 不导出 Windows 凭据目标名。导入时为每组配置生成新的本机 ID 和凭据目标，防止与原设备或已有配置混用。
- 解密后先校验 schema、大小、数量、重复项、端点和 Provider，再显示来源版本、时间、配置数、含 Key 数、自定义 Provider 数和导入后的当前配置。
- 用户确认后替换目标设备上的全部 AI 配置和自定义 Provider 预设，其他应用设置不变。
- 先写入全部新凭据，再原子保存预设和普通设置；任一步失败都会删除本次已写入的新凭据并保留原配置。提交成功后再清理旧凭据。
- 普通 `settings.json`、诊断、日志、每日备份、测试 fixture 和界面摘要仍不得出现 Key。
- 保留原来的无 Key JSON 导入导出，供公开模板和低敏迁移使用；它不会覆盖当前配置，导入项仍需补 Key 和重新验证。

验收条件：

1. 两组以上不同供应商配置可完整导出，并在另一空白数据目录导入后立即加载原当前配置和正确 Key。
2. 密文文件中搜索不到 Key、端点、模型或配置名称；错误口令、任意密文篡改、未知字段和超限文件都被拒绝。
3. 导入预览不显示 Key；用户取消时不写普通设置、预设或凭据。
4. 第二个凭据写入失败等中途故障不会替换原配置，第一个临时凭据会清理。
5. 自定义 Provider 与启用状态一并迁移，内置 ID 冲突或无效端点阻断整个导入。
6. 完整包最大 4 MB、最多 100 组配置和 32 个自定义 Provider；单个 Key 按 Windows 凭据容量限制校验。

### EXT-16 GitHub Release 在线更新

状态：**0.15.0 已实施，等待完整发布门禁。**

- 每次正常启动异步检查一次指定 GitHub 仓库的最新稳定 Release；失败不阻止启动，不自动下载。
- 设置可选运行期间周期检查，周期为 1～168 小时；Windows 系统代理自动生效。
- 国内网络可填写用户信任、仅 HTTPS 且恰含一个 `{url}` 占位符的加速模板；失败后回退官方地址。
- 私有仓库令牌只保存到 Windows 凭据管理器。带令牌时忽略第三方加速模板，只请求 GitHub 官方 API 或系统代理。
- 只接受精确版本安装器与 `SHA256SUMS.txt`，限制元数据、清单和安装器大小；下载写临时文件，SHA-256 匹配后才发布到更新目录。
- 校验通过仍不静默安装；应用显示确认，处理未保存 AI 编辑后才启动安装器并退出。

验收条件：一次进程生命周期只执行一次启动检查；周期设置重启保持；相同/旧版本不提示；无效元数据、HTTP、重定向、文件名、大小和校验和均停止；令牌不出现在普通文件且绝不发往加速域名；取消或失败保留当前版本。

## 3. 后续 AI 能力

### EXT-12 今日安排与待办整理

目标版本：0.16.x；优先级：P1；状态：**已由 0.16.0 的 TODAY-01～05 实现时间块安排，拆分与自动延期未纳入该版。**

实际交付范围按 0.16.0 当前代码重新收敛为 1～12 条明确选择、AI 或本地时间块草稿、逐项排除、原子确认和整批撤销；详情与未验收边界见 [0.16.0－功能扩展计划](0.16.0－功能扩展计划.md)。下面保留 0.15.0 规划时的原始设想，用于解释范围变化，不作为当前行为说明。

用户在待办页勾选若干待办后，AI 可生成“今日安排草稿”：建议顺序、预计时间段、可拆分步骤和需要延期的项目。发送前必须显示将提交的标题、日期和备注字段；默认只发送勾选项，不读取已完成项或整库。输出沿用结构化草稿，逐项显示新增、改期和拆分动作，用户可取消单项或全部，确认后才写入 TodoStore。没有 AI 配置或请求失败时，仍提供本地的今天/逾期/无日期筛选。

验收重点：跨午夜和时区正确；重名项绑定稳定 ID；冲突时间有提示；取消不写入；一次确认支持整体撤销；请求和诊断不记录待办正文。

### EXT-13 从已选内容提炼摘要与待办

目标版本：0.17.x；优先级：P1；状态：**后续，未实现。**

在搜索结果中由用户主动选择一个受支持的文本文件后，提供“生成摘要”和“提取待办草稿”。读取范围只限本次选中的文件，不沿用元数据索引权限推断正文授权；发送前显示文件名、类型、大小、截断情况和将发送的文本预览。首版只支持明确编码、容量受限的纯文本/Markdown，不处理 Office、PDF、图片 OCR、音视频或整个目录。

输出不能直接修改源文件。摘要只在临时结果区显示；提取的待办进入现有确认流程。撤销授权、文件变化、超限、二进制内容或编码不确定时停止处理，并提供打开文件或手工录入入口。

### EXT-14 提醒冲突与过期项检查

目标版本：0.17.x；优先级：P1；状态：**后续，未实现。**

用户主动选择日期范围和待办后，让 AI 检查重复安排、过密时间段、已过期项和缺少日期的项目，并生成改期或合并建议。规则计算、时区换算和实际写入继续由本地代码完成，AI 只输出建议意图。每个建议需显示原值、新值和影响的重复范围；“仅此次”与“整条规则”必须再次选择。

验收重点：不把提醒投递历史当作用户已读；不静默完成待办；重复规则修改不误伤例外；无网络时本地冲突标记仍可用。

### EXT-15 AI 配置健康检查与脱敏诊断说明

目标版本：0.18.x；优先级：P2；状态：**后续，未实现。**

在现有模型列表验证、最小生成验证和白名单诊断基础上，增加一页可操作健康摘要：凭据是否存在、端点格式、最近验证时间、模型是否可见、生成能力是否单独验证，以及 Provider 预设是否过期。用户可选择把稳定错误码、耗时区间、版本和功能开关交给 AI 生成排查步骤；不发送 Key、完整端点查询、服务响应正文、文件路径、待办内容或搜索词。

验收重点：诊断输入在发送前可查看和复制；建议不能自动改 Key、端点或模型；任何修改仍需重新测试后保存；离线时继续显示本地检查结果。

## 4. 暂不实施

当前不实施通用聊天窗口、后台长期对话记忆、自动浏览或修改文件、任意脚本/插件执行、无人确认的待办与提醒变更、全盘正文索引、跨设备云同步、团队协作、账号画像、广告、订阅、商城、付费角色或金融功能。外部 2D 角色包和内容检索原型继续留在 `tests/prototypes`，通过独立 RFC、许可、隐私和资源门禁前不进入产品。

## 5. 版本与文档规则

扩展计划文件从本版本起统一命名为 `<版本号>－功能扩展计划.md`，使用软件 SemVer 和全角连接号 `－`。新版本开始规划时创建对应文件；旧版本计划可作为历史依据保留，但不得继续承担当前状态入口。当前实现、测试和发行状态分别以 [CURRENT_STATUS.md](CURRENT_STATUS.md)、[TEST_PLAN.md](TEST_PLAN.md) 和当次 `docs/release/<version>-test-report.md` 为准。
