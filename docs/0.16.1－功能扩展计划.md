# 0.16.1－功能扩展计划

> 版本定位：在 0.16.0 已有能力上做补丁级精进，不新增功能入口，不改变用户数据格式。

## 1. 目标与原则

0.16.1 聚焦“正确、可恢复、易理解”。本版本只修正今日安排和 GitHub 在线更新中的边界行为，并补齐对应自动化回归测试、用户说明和发布证据。

- 保持现有桌宠、搜索、待办、AI 配置、今日安排和在线更新工作流不变。
- 不增加第三方依赖，不扩大 AI 数据发送范围，不迁移现有用户配置。
- 所有失败路径保持原子性：生成失败不修改待办，批量写入或撤销冲突时整批不落盘，更新检查失败不破坏已有更新状态。

## 2. 按顺序实施

### OPT-161-01 今日安排避让既有时间块（P0）

**现状问题**：选中的待办会被重新安排，但未选中的待办可能已经有今日时间块；当前本地安排和 AI 结果校验只检查新草稿内部是否重叠，可能生成与既有安排冲突的草稿。

**优化内容**：

1. 从未选中的待处理事项中提取当天有效的开始/结束时间，仅作为匿名占用时间段参与计算。
2. 本地安排按 15 分钟边界开始，每项保持 30 分钟，并自动跳过占用时间段。
3. AI 请求只发送所选事项的正文；未选中事项仅发送匿名的开始/结束时间，不发送标识、标题、备注或截止信息。
4. AI 返回结果除现有校验外，还必须拒绝与匿名占用时间段重叠的草稿。
5. 界面隐私说明明确区分“所选正文”和“匿名占用时间”。

**验收**：本地和 AI 草稿均不与已有时间块重叠；未选中事项正文不会进入 AI 请求；跨日或无效占用时间不会进入请求。

### OPT-161-02 时间边界与草稿反馈精确化（P1）

**现状问题**：本地安排的 15 分钟取整可能保留更小的时间精度；生成结果没有说明是否避让了既有安排。

**优化内容**：

1. 本地起始时间精确到整分钟，清除秒和更小精度。
2. 草稿生成消息显示已避让的既有时间段数量，便于用户理解安排结果。
3. 当今天剩余空闲时间不足时保持不写入，并给出减少选择或调整既有安排的可执行提示。

**验收**：任意带秒和毫秒的当前时间都生成准确的下一个 15 分钟边界；反馈数量与请求中的匿名占用时间一致。

### OPT-161-03 批量应用与撤销冲突提示分离（P1）

**现状问题**：批量应用草稿和撤销旧安排共用“草稿生成后被修改”的提示，撤销失败时语义不准确。

**优化内容**：

1. 应用草稿遇到并发修改时继续提示重新生成。
2. 撤销旧安排遇到后续修改时提示不能用旧快照覆盖新内容。
3. 两条路径继续保持单次原子写入和整批失败。

**验收**：自动化测试分别覆盖应用与撤销的过期写入，验证错误文案和无部分写入。

### OPT-161-04 在线更新凭据与失败恢复（P0）

**现状问题**：令牌输入框中的未保存内容会被“立即检查”临时使用；周期检查的瞬时失败会清除此前已发现的可下载更新。

**优化内容**：

1. 检查和下载只读取 Windows 凭据管理器中已明确保存的令牌。
2. 输入框中的未保存令牌不发送到网络，保存成功后清空输入框。
3. 检查结果为“失败”或用户取消时保留此前已发现的更新和下载入口。
4. 明确说明保存令牌后只连接 GitHub 官方地址或系统代理，不使用自定义加速模板。

**验收**：未保存令牌不会传给更新客户端；已保存令牌会传递；失败检查后仍可下载先前发现的版本；确认已是最新版本时正确清除旧状态。

## 3. 自动化与发布门禁

完成实现后依次执行：

1. 新增和运行今日安排、批量存储、更新 ViewModel 的定向回归测试。
2. 运行 `scripts/validate-project.ps1` 与 `scripts/test.ps1 -CI`。
3. 使用 `scripts/bump-version.ps1` 将版本升级到 `0.16.1`，同步应用元数据、安装器、README、变更日志和所有当前文档。
4. 再次运行完整 CI 测试，生成 Release 构建。
5. 运行便携版与安装版打包，校验 SHA-256，并执行安装、启动、升级/卸载、便携运行、托盘和自启烟雾测试。
6. 运行 Windows UI E2E、性能、安全凭据、签名及可用硬件门禁，按实际结果记录 PASS、FAIL 或 SKIP。
7. 只有全部正式发布门禁通过时才创建 `v0.16.1` 标签和 GitHub Release；否则推送 `main` 和候选资产/证据，并明确保留为候选版本。
