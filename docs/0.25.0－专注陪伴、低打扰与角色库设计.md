## 1. 版本决策

0.25.0 只交付当前代码和现有资源能够形成完整闭环的三项能力：

1. **专注会话**：从待办或无关联状态启动计时，支持暂停、继续、提前结束、到时确认和本地复盘。
2. **低打扰桌宠**：专注时停止自主漫游和随机气泡，可选点击穿透；其他应用进入同屏全屏后可自动隐藏桌宠。
3. **内置角色库优化**：继续使用 base、hero、skeleton、monster 四个 CC0 角色，为它们提供图片预览、清晰选中状态、许可信息和可靠切换。

三项能力组成同一条用户路径：用户选择任务并开始专注，桌宠立即安静下来；需要全屏或操作桌面时不遮挡；计时结束后给出一次明确反馈；结果可在当天复盘中查看。角色库只改善现有四个角色的选择体验，不依赖外部素材。

## 3. 产品目标与质量原则

### 3.1 产品目标

- 用户不离开待办页即可在 15 秒内开始一次专注。
- 专注状态必须由文字和控件明确表达，宠物动画只是辅助反馈。
- 桌宠进入专注后保持安静，不用重复动作抢夺注意力。
- 自动隐藏或点击穿透都必须可解释、可关闭、可恢复。
- 角色切换能看到真实预览，失败时不保存无效选择。
- 全部数据保留在本机，不调用 AI、遥测或新在线服务。

### 3.2 交付原则

- 不增加新的主页面：专注入口位于待办页，角色库和低打扰设置位于现有设置页。
- 不增加第三方 NuGet、媒体文件或新的联网依赖。
- 不修改 Todo 与 DailyJournal 的既有 schema；专注会话独立存储，只向复盘提供只读聚合。
- 不用 `death` 表达专注失败，不把结束计时设计成惩罚。
- 保持单宠窗口模型，不改变现有工具窗、提醒和托盘的单实例关系。

## 5. 专注会话体验

### 5.1 开始会话

1. 用户进入“待办 → 清单”，选中一个未完成事项。
2. “专注陪伴”默认折叠；标题行显示最近选择的时长，没有活动会话时不占用大块空间。
3. 展开后默认关联当前选中事项。用户可点击“使用当前选择”更新关联，或清除关联。
4. 用户选择 15、25、50 分钟，或输入 5～180 的整数分钟。
5. 开始按钮上方明确显示“本次计时不会自动完成待办”。
6. 点击“开始专注”后固定 Todo ID 与计划时长；之后列表选择变化不影响本次会话。

若选中事项已完成、已删除或是独立提醒，界面不自动关联，并说明原因。无关联状态始终允许开始。

### 5.2 运行、暂停与恢复

运行状态固定展示：

- 剩余时间，格式为 `MM:SS`，超过 99 分钟时为 `H:MM:SS`；
- “正在专注”或“已暂停”文字状态；
- 关联事项的当前标题，事项已删除时显示“原关联事项已不存在”；
- 暂停/继续和结束按钮。

暂停后不累计时间。继续时从剩余值开始，不新建会话。重复点击、键盘连按或迟到的旧命令必须通过会话 ID 与 revision 拒绝，不能生成两个活动会话。

### 5.3 到时与提前结束

- 正常到时：状态变为 `Completed`，剩余时间固定为零，只提交一次完成结果。
- 提前结束：先确认“将按实际时长保存”，确认后状态变为 `EndedEarly`。
- 两种结果都不修改 Todo；存在有效关联时额外显示“完成关联待办”，用户确认后调用现有完成命令。
- 用户关闭完成提示后，折叠区回到可开始状态；历史记录仍保留。
- 动画被系统关闭时，只显示文字状态和完成气泡，不强制播放动作。

### 5.4 异常与恢复

- 应用运行期间用单调时钟计算当前段累计值，避免系统时钟微调造成倒计时跳变。
- 每次开始、暂停、继续、结束和到时都原子保存；最多一个 `Running` 或 `Paused` 会话。
- 正在运行时退出并重新启动：计划结束时间未到则按持久化时间继续；已到则完成一次。
- 暂停时退出并重新启动：保持暂停，不因关闭时长增加累计值。
- 休眠恢复按同一规则处理；应用不承诺在进程未运行时准点弹出通知。
- 检测到系统时间大幅回拨或持久化数据矛盾时，自动暂停并提示用户继续或结束，不自行猜测。
- 存储失败时保留当前内存状态和原文件，禁用会产生进一步分歧的命令，并提供重试。

## 6. 数据模型与复盘

### 6.1 FocusSessionStore

新增 `%APPDATA%/WindowsAiDesktopPet/focus-sessions.json`：

```json
{
  "schemaVersion": 1,
  "revision": 12,
  "lastDurationMinutes": 25,
  "activeSessionId": "9d3f...",
  "sessions": [
    {
      "id": "9d3f...",
      "todoId": "47c2...",
      "status": "Running",
      "plannedSeconds": 1500,
      "accumulatedSeconds": 420,
      "startedAt": "2026-09-17T15:00:00+08:00",
      "lastResumedAt": "2026-09-17T15:08:00+08:00",
      "endedAt": null
    }
  ]
}
```

约束：

- `status` 只允许 `Running`、`Paused`、`Completed`、`EndedEarly`。
- `plannedSeconds` 为 300～10,800；累计值为 0～计划值。
- 只有 `Running` 或 `Paused` 可被 `activeSessionId` 引用，且最多一个。
- 时间保存带偏移的 ISO 8601；聚合时使用结束当日的本地日期。
- 不复制待办标题或备注。读取标题只通过当前 Todo ID 投影，删除待办后不保留正文副本。
- 最多保存 10,000 条会话且文件不超过 16 MiB；接近上限时提示用户在维护页导出备份后清理最旧历史，不静默删除。
- 损坏文件保留原件并阻止空数据覆盖；UI 和日志只记录稳定错误类别。

### 6.2 复盘投影

复盘页的“当日概览”增加：

- 完成专注次数：`Completed` 数量；
- 专注总时长：`Completed` 与 `EndedEarly` 的累计秒数相加后显示为小时/分钟；
- 提前结束次数：`EndedEarly` 数量。

投影不写入 journal 正文或跨日快照，不列 Todo ID。单日 Markdown 导出增加同样三项数字，格式稳定且不包含活动窗口或输入信息。

## 7. 低打扰状态协调

### 7.1 状态优先级

桌宠可见性从高到低处理：

1. 应用退出；
2. 用户手动隐藏；
3. 同屏全屏自动隐藏；
4. 正常显示。

专注安静状态与点击穿透是显示后的独立属性：专注控制动画、漫游和气泡；点击穿透只控制宠物窗口的命中。这样可以避免退出全屏时错误取消专注或错误显示用户手动隐藏的桌宠。

协调器为每种效果保留原因，不使用单一布尔值覆盖多个来源。全屏状态解除时，仅删除 `Fullscreen` 原因；手动隐藏仍然有效。

### 7.2 专注安静状态

进入会话后：

- 立即中断在途自主漫游并回到当前位置，不移动到新位置；
- 停止低频自主动作和随机陪伴气泡；
- 停止鼠标朝向采样，固定正面 `idle` 循环；
- 继续允许用户主动拖动桌宠；拖动期间临时使用现有 `jump`，释放后回到正面 `idle`；
- 继续允许正式提醒气泡显示，但不伴随自主漫游；
- 暂停会话仍保持安静状态，结束或到时后恢复用户原有的漫游、气泡和朝向设置。

恢复时读取进入专注前的用户设置，不把临时状态写回长期外观偏好。

### 7.3 全屏检测与恢复

新增 `ForegroundFullscreenMonitor`，每 500 ms 使用标准 Win32/DWM 只读接口检查：

- 前台顶层窗口是否可见、未最小化且不属于本进程；
- 窗口扩展边框是否与所属显示器边界在 2 个物理像素内吻合；
- 前台窗口与桌宠中心点是否属于同一显示器；
- 连续两次结果一致后才切换，避免边界抖动。

进入全屏时记录“自动隐藏前桌宠是否可见”，隐藏桌宠和气泡。离开全屏时，只有桌宠此前可见且期间未发生手动隐藏，才恢复桌宠；工具窗始终不自动重新弹出。检测失败保持当前状态，不允许因一次异常永久隐藏。

### 7.4 点击穿透

- 只在存在活动专注会话且用户已启用选项时设置宠物窗口扩展样式。
- 工具窗、提醒中心和托盘不穿透。
- 托盘在生效期间显示“恢复桌宠交互”，执行后关闭本次会话的穿透效果，但不结束计时。
- 打开设置、专注结束、窗口句柄重建、异常恢复和应用退出前必须移除穿透样式。
- 设置失败时不重试循环，直接保持可交互并给出一次稳定提示。

## 8. 内置角色库体验

### 8.1 角色卡

现有文字选项升级为两列角色卡：

| 角色 ID | 显示名称 | 预览来源 |
| :--- | :--- | :--- |
| `hero` | 红帽勇者 | `idle_down_01.png`～`idle_down_04.png` |
| `base` | 方块伙伴 | `idle_down_01.png`～`idle_down_04.png` |
| `skeleton` | 骷髅小队长 | `idle_down_01.png`～`idle_down_04.png` |
| `monster` | 森林怪兽 | `idle_down_01.png`～`idle_down_04.png` |

每张卡固定包含 64×64 预览、名称和选中标记。选中角色可以循环四帧 `idle`；其他卡只显示第一帧，避免设置页同时运行多组动画。系统关闭客户端动画时全部显示静态第一帧。

卡片下方统一显示资源来源和许可，不为四个角色重复制造不同的来源描述。许可入口打开仓库内随软件分发的 `License.txt`，失败时给出可复制的本地相对位置，不联网获取许可正文。

### 8.2 切换事务

1. 角色库从 manifest 读取合法角色 ID，只展示四个已声明且首帧可解码的角色。
2. 用户选择角色后，先验证对应缓存和首帧，再原子保存 `preferredCharacter`。
3. 保存成功后调用现有 `PetWindow.SetCharacter` 的无持久化切换入口，立即更新桌宠。
4. 保存失败时列表恢复原选中项；运行时角色不变。
5. 极少数应用阶段失败时，回滚设置与运行时到原角色，并显示稳定错误。
6. 启动时设置无效或目标首帧失败，使用 manifest 的 `preferred`，仍失败则使用首个可解码角色；不显示空白窗口。

为避免双重保存，`PetWindow.SetCharacter` 需拆成纯运行时切换和由上层负责的设置事务。

## 9. 界面布局

### 9.1 待办页

“专注陪伴”位于手动编辑器之后、今日安排之前，默认折叠。活动会话、到时状态或错误出现时自动展开。

折叠标题始终显示：

- 无会话：`专注陪伴 · 25 分钟`；
- 运行中：`正在专注 · 18:42`；
- 已暂停：`专注已暂停 · 18:42`；
- 已到时：`本次专注完成`。

展开内容只保留当前阶段需要的控件：未开始时显示关联、时长和开始；运行时显示计时与暂停/结束；暂停时显示继续/结束；到时后显示完成关联待办和关闭。隐藏无效操作，减少误触。

### 9.2 设置页

现有“外观”分组调整为：

1. **内置角色**：四张角色卡、来源和许可。
2. **外观与动态**：保留漫游、提醒气泡动画、朝向跟随。
3. **低打扰**：同屏全屏时隐藏桌宠、专注时点击穿透，两项均默认关闭并附恢复说明。

低打扰设置采用现有显式保存模式：无修改时禁用保存，保存失败保留草稿；离开设置不自动应用，当前进程内再次进入仍保留未保存草稿。

### 9.3 托盘

活动会话期间新增：

- `暂停专注` 或 `继续专注`；
- `结束专注…`；
- 点击穿透生效时的 `恢复桌宠交互`。

原有显示/隐藏桌宠、工具窗、设置、快速待办和退出入口保持不变。托盘文案与待办页读取同一会话快照，不能各自维护状态。

### 10.3 状态模型

```text
Idle
  └─ Start ───────────────> Running
Running
  ├─ Pause ───────────────> Paused
  ├─ End early + confirm ─> EndedEarly
  └─ Remaining = 0 ───────> Completed
Paused
  ├─ Resume ──────────────> Running
  └─ End early + confirm ─> EndedEarly
```

每次转换必须同时满足当前会话 ID、期望状态和 revision。UI 命令完成前禁用同一按钮，存储提交成功后再发布新快照。

## 11. 隐私、无障碍与性能

### 11.1 隐私与安全

- 所有新数据仅保存在当前 Windows 账户数据目录。
- FocusSessions 不进入搜索索引、AI 请求、日志、诊断正文或遥测。
- 全屏检测只保留当前布尔结果和稳定错误类别，不持久化窗口句柄或活动时间线。
- 日志不得记录 Todo ID 对应正文、精确专注起止时间、完整文件路径或原始异常。
- 点击穿透和全屏隐藏不绕过 Windows 权限、安全桌面或其他进程边界。

### 11.2 无障碍

- 计时状态至少同时由文字、AutomationProperties 和控件可用状态表达。
- 角色选中状态同时使用勾选图形和文字，不只改变颜色或边框。
- 动画遵守 `SystemParameters.ClientAreaAnimation`；关闭动画不影响计时和操作反馈。
- 200% 缩放下专注区允许纵向滚动，角色卡不横向溢出。
- 高对比度下使用系统颜色回退，预览图片之外的所有信息都有文本。

### 11.3 性能预算

- 专注倒计时 UI 每秒更新一次，不进行逐帧磁盘写入。
- 会话只在状态转换和必要恢复点保存，不每秒保存。
- 全屏检测间隔 500 ms，状态去抖后才触发 UI 操作。
- 角色库只解码每个角色的一张冻结首帧，不启动独立预览动画。
- 启用全部新功能后，正常空闲 CPU 仍需满足项目 ≤2% 的既有预算，工作集仍需满足 ≤300 MB。
