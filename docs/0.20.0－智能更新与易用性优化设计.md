## 1. 背景与问题

0.19.0 的更新功能已经具备启动检查、周期检查、下载进度、SHA-256 校验和安装前确认，但设置页要求普通用户理解 `{url}` 模板、HTTPS 代理、GitHub 令牌和私有仓库权限。这些内容不属于桌宠用户的核心任务，也会把网络差异处理转嫁给用户。

本版本把复杂度收回应用内部：用户只决定“是否周期检查”和“现在是否检查”，应用自动选择 GitHub 官方或内置国内网络加速线路。更新仍然只读取固定公开仓库的稳定 Release，不自动下载安装，不改变当前安装前确认流程。

## 2. 线路核验与约束

### 2.1 2026-09-13 核验结果

| 入口 | GitHub 静态文件 | GitHub Release API | 产品用途 |
| :--- | :---: | :---: | :--- |
| `https://api.github.com` / `https://github.com` | PASS | PASS | 官方检查与最终回退 |
| `https://gh-proxy.com/{url}` | PASS | PASS | API 与下载加速回退 |
| `https://ghfast.top/{url}` | PASS | 403 | 仅下载加速 |
| `https://ghproxy.net/{url}` | PASS | 403 | 仅下载加速 |

核验使用公开 GitHub 原始文件和公开 Release API，只验证当日 HTTPS 可达性与响应类型，不构成第三方服务长期可用性、运营主体或内容真实性背书。服务能力来源同时参考各服务首页，以及 GitHub 官方 Release API 对 `browser_download_url`、`size`、`digest` 的定义：

- <https://docs.github.com/en/rest/releases/releases>
- <https://docs.github.com/en/rest/releases/assets>
- <https://gh-proxy.com/>
- <https://ghfast.top/>
- <https://ghproxy.net/>

### 2.2 固定边界

1. 加速域名只存在于代码中的只读路由表，不写入用户设置，不提供输入框。
2. 更新请求不携带 GitHub Token、Cookie、查询词、路径或其他个人数据。
3. 元数据先尝试 GitHub 官方 API，失败后再尝试具备 API 能力的内置线路；单条超时后自动继续，不阻止桌宠启动。
4. 安装器与校验清单优先尝试内置下载线路，全部失败后回退 GitHub 官方。
5. 第三方服务变化时只影响对应候选线路；不得让单一线路成为更新功能的唯一依赖。
6. 界面只显示“GitHub 官方”“智能加速线路”或“全部线路不可用”，不暴露域名、模板和鉴权术语。

## 3. 需求设计

### UPDATE-200-01 内置分级路由

- 元数据路由顺序：GitHub 官方 API → `gh-proxy.com`。
- 下载路由顺序：`gh-proxy.com` → `ghfast.top` → `ghproxy.net` → GitHub 官方。
- 每条候选包含内部显示名、能力和 URL 包装规则；去重后顺序执行。
- 检查结果与下载结果返回实际成功的用户级线路名称，供状态区展示。

### UPDATE-200-02 Release 资产规范化

- 使用 GitHub 官方字段 `browser_download_url`，不再依赖需要鉴权媒体类型的资产 API URL。
- Release 页面必须精确属于 `mawenshui/windows-ai-desktop-pet` 和当前稳定标签。
- 安装器、`SHA256SUMS.txt` 的下载地址必须精确属于固定仓库、固定标签和固定文件名。
- 元数据中的安装器大小必须大于 0 且不超过 200 MiB；清单不超过 1 MiB。

### UPDATE-200-03 下载安全

- 只允许无用户信息的 HTTPS。
- 最终响应只能停留在请求线路主机或 GitHub 官方/CDN 主机集合，拒绝跳往任意第三方主机。
- 若 Release 元数据提供 `sha256:` digest，必须与清单中的安装器哈希一致。
- 安装器仍先写 `.download`；大小或哈希不符立即删除，现有版本不变。
- 不向任何内置线路发送 Authorization；0.19.0 及更早版本遗留的自定义模板和更新令牌不再参与请求。

### UPDATE-200-04 设置页减负

- 删除“国内网络与自定义代理”展开区、模板输入框、Token 输入框及保存/清除按钮。
- 保留周期检查、周期小时、保存、立即检查和发现更新后的下载操作。
- “立即检查”成为本区主操作；设置保存保持次要层级。
- 新增固定的“智能线路”状态带，说明应用会自动选择线路，不要求用户配置。

### UPDATE-200-05 状态与恢复

| 状态 | 状态带 | 主状态 |
| :--- | :--- | :--- |
| idle | 智能线路已开启 | 启动时检查一次 |
| checking | 正在选择可用线路 | 正在检查更新 |
| up-to-date | 本次通过官方/智能线路完成 | 当前版本最新 |
| available | 本次通过官方/智能线路完成 | 发现版本，可下载 |
| downloading | 正在自动选择下载线路 | 保留百分比进度 |
| ready | 安装包已校验 | 等待用户确认安装 |
| error | 官方与内置线路均不可用 | 稍后重试；保留既有可用版本 |

状态变化使用可见文本和 UI Automation polite live region；不能只依赖颜色。失败不清除此前发现的版本，取消不删除已经校验完成的安装器。

### UPDATE-200-06 兼容迁移

- 设置 schema 保持 5；保留 `accelerationTemplate` 字段的反序列化兼容，但规范化后置空且业务不再读取。
- 旧版 Windows Credential Manager 中的更新令牌不再读取或发送；为避免静默删除用户数据，只在原有卸载清理路径中移除。
- AI Key 与更新功能完全隔离，不受本次变更影响。

### UPDATE-200-07 回归与文档

- 单元测试覆盖路由顺序、API/静态能力分离、全部线路失败、匿名请求、规范化 URL、重定向主机、大小、digest 与清单一致性。
- ViewModel 覆盖只保存周期设置、状态带、失败保留发现版本和下载成功线路。
- XAML/生命周期覆盖专业输入移除、主次操作、可见焦点和 live region。
- 同步 PRD、工程规范、技术设计、用户手册、测试计划、当前状态、README、CHANGELOG 和 Release notes。

## 4. 实施顺序

1. **路由内核**：建立元数据/下载只读路由表和成功线路结果。
2. **协议与安全**：改用规范化 `browser_download_url`，增加仓库/标签/主机、大小和 digest 校验。
3. **ViewModel**：移除用户模板/令牌状态，接入智能线路状态带，保持取消与恢复语义。
4. **设置界面**：删除专业配置区，调整按钮层级、说明、自动化名称和焦点入口。
5. **兼容迁移**：忽略并规范化清空旧模板；保留卸载时的遗留凭据清理。
6. **自动化测试**：依次补齐 SystemIntegration、ViewModel、存储、XAML 和生命周期回归。
7. **版本与交付**：升级 0.20.0，同步文档，完整 CI、系统/UI/性能、打包和烟雾测试；受限项目如实 PASS/FAIL/SKIP。

后续步骤不得在前一步测试失败时继续宣称完成；线路在线探测不进入 CI，CI 只使用 fake `HttpMessageHandler`，避免依赖第三方实时状态。

## 5. 验收标准

| ID | 验收要求 |
| :--- | :--- |
| AC-UPDATE-200-01 | 新安装用户无需填写地址或令牌即可检查更新；设置页不存在 `{url}`、代理模板或 Token 输入 |
| AC-UPDATE-200-02 | 官方 API 成功时不访问元数据加速线路；官方失败时自动回退一条 API 线路 |
| AC-UPDATE-200-03 | 下载按三条内置线路和官方地址顺序恢复；单条失败不清除更新状态 |
| AC-UPDATE-200-04 | 所有内置线路请求均无 Authorization，旧 Token 不参与检查或下载 |
| AC-UPDATE-200-05 | 非固定仓库/标签/文件名、非 HTTPS、用户信息 URL、越界大小或未知重定向主机全部拒绝 |
| AC-UPDATE-200-06 | 清单哈希与元数据 digest（存在时）不一致时删除临时文件，不触发安装 |
| AC-UPDATE-200-07 | idle/checking/success/error/download/ready 状态均有可见文字和自动化播报，键盘可执行主要操作 |
| AC-UPDATE-200-08 | 旧设置可读取，旧模板被忽略并在下次保存时清空；更新凭据仅保留原卸载清理，不再发送 |

## 6. 非目标与发布边界

- 不自动安装、不静默退出、不绕过 Windows UAC 或 SmartScreen。
- 不引入后台常驻服务、自建 CDN、P2P 下载或动态远程下发代理列表。
- 不承诺第三方线路长期可用；正式发布前必须重新核验，失效线路应通过代码版本更新替换。
- SHA-256 与 digest 不能替代 Authenticode；未配置受保护签名证书时，稳定 Release 仍被签名门禁阻断。
