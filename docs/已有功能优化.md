## 1. 文档目的与结论

当前项目已经形成可运行的 WPF/.NET 8 桌面应用，主要功能链路均有真实源码，不再是文档或原型阶段。当前源码直接运行 `dotnet test src/AiPet.sln --configuration Release` 可完成 **138 项单元及 WPF 交互测试，0 失败、0 跳过**。0.8.1 修复了 AI 供应商下拉框选中显示、连接测试通过后的保存状态和快捷入口空状态叠加问题。但 `0.8.1` 仍属于发布候选：完整安装、启动、凭据、系统通知、休眠恢复、卸载、多屏和缩放验证尚未全部在普通交互式 Windows 会话完成，集成测试与系统级 E2E 目录也尚未形成可执行套件。

后续优化应遵循以下顺序：

1. **先保证验证结果可信**：修复测试入口可能误选 `build/` 旧副本的问题，补齐系统级验证、性能基线和发布证据。
2. **再补齐已承诺能力的闭环**：优先完成首次搜索授权引导、范围状态与取消、AI 凭据清除、托盘状态同步、提醒受限状态等 P0 行为。
3. **随后提高核心链路质量**：搜索采用可取消的流式索引与事务切换，提醒感知休眠/时间变化，数据具备迁移和可解释恢复。
4. **最后扩展体验上限**：增量索引、相关性排序、原生通知、主题、无障碍、动画偏好和模块重构可按独立 minor 版本推进。

本轮优化不应把“新增更多功能”置于“现有功能可验证、可恢复、可发布”之前。

## 2. 事实边界与优先级

### 2.1 当前事实边界

- `VERSION` 当前为 `0.8.1`。
- 桌宠、工具窗口、搜索、快捷入口、AI 配置、待办和提醒均已有生产源码。
- 当前测试重心仍是 `tests/unit/AiPet.Tests.Unit`；`tests/integration/` 与 `tests/e2e/` 还没有真实测试工程。
- 当前提醒通道是页内提醒加 WinForms `NotifyIcon` 托盘气泡；应用完全退出时不能准点唤醒。
- 当前搜索只处理用户授权目录的名称/路径元数据以及开始菜单和 `App Paths` 应用入口，不做全文、OCR 或语义搜索。
- AI Key 使用 Windows 凭据管理器保存；普通设置只保存非敏感配置和凭据引用。
- 现有便携版、安装版和校验和不等于正式发布完成；代码签名、交互式烟雾测试、版本标签和 GitHub Release 仍是独立门禁。

### 2.2 优先级定义

| 优先级 | 定义 | 版本建议 |
| :--- | :--- | :--- |
| P0 | 影响数据正确性、隐私、主路径可用性、验收真实性或正式发布，未完成前不应宣布发布完成 | 向后兼容修复可进入 patch；新增用户可见闭环按 SemVer 评估 minor |
| P1 | 明显改善性能、稳定性、可恢复性、可访问性或高频操作效率 | 通常进入后续 minor，低风险修复可拆为 patch |
| P2 | 提升体验上限或为后续扩展打基础，但不阻断当前核心使用 | 独立需求或 RFC 后排期 |

## 4. 分模块优化方案

### 4.1 桌面宠物

**当前基础**

- 透明、无边框、置顶窗口已实现，桌宠可拖动并按账户保存位置。
- 单击、双击和拖动通过阈值及延迟仲裁，双击不会误开工具窗口。
- RGS 帧缓存、透明裁切、五方向资源与镜像派生已实现。
- 鼠标远离后回正，空闲语句、动作和短距离漫游可被用户交互中断。

**P0 优化**

1. 在 Windows 10/11、100%～200% 缩放、负坐标副屏、主副屏切换、任务栏不同位置下完成实机矩阵，验证宠物不会丢失、跳屏或产生错误命中区域。
2. 增加锁屏、解锁、显示器断开/重连、RDP 切换后的恢复处理；不可恢复时夹取到最近工作区并仅记录脱敏错误类别。
3. 对连续运行 30 分钟、拖动 100 次、单/双击交替和工具窗跟随建立自动化或可重复人工脚本，形成 AC-01/02 的验收证据。

**P1 优化**

1. 桌宠隐藏、锁屏或系统关闭动画时暂停不必要的帧、方向和空闲计时器；恢复后只启动一组调度器，避免重复订阅。
2. 记录冷启动帧缓存时间、空闲 CPU、工作集和拖动帧率，以实测结果锁定资源预算，不在数据不足时先承诺数值。
3. 增加“空闲漫游”“语句气泡”“跟随鼠标”“降低动态效果”独立开关，并与 Windows 动画偏好一致。
4. 把可见角色边界与窗口命中区域做回归检测，减少透明留白吞掉桌面点击。

**验收口径**

- 工具窗口唤出 P95 满足 PRD 的 `≤ 300ms`。
- 30 分钟常驻不消失、不崩溃、不重复创建窗口或计时器。
- 多屏和 100%～200% 缩放矩阵下宠物始终至少保留可拖动区域。
- 关闭动态效果后不发生自动漫游，基础点击和拖动仍可用。

### 4.2 工具窗口、导航与设置

**当前基础**

- 单实例气泡窗口可锚定宠物，在空间不足时上下切换并限制在工作区内。
- 每次普通唤出回到主页；待办提醒可直接进入待办页；`Esc`、关闭按钮和失焦可收起。
- “常驻”和“置顶”是独立状态，并可持久化。

**P0 优化**

1. 完成 SET-01 的未保存状态闭环：AI 配置已经修改但未保存时，显式关闭或切离设置页应提供保存、放弃、取消；自动失焦收起不应误丢输入。
2. 明确所有唤出来源的落点规则：宠物/第二实例进入主页，托盘“设置”进入设置，提醒点击进入对应待办；重定位不得改变页签和焦点。
3. 验证 200% 缩放和窄工作区下的编辑器、确认卡、错误信息及底部按钮均可滚动到达，不能只测试控件是否存在。
4. 将搜索中、保存成功、提醒失败等关键状态配置为 UI Automation 可感知的 Live Region，不只依赖颜色或瞬时文本。

**P1 优化**

1. 将 `PetToolWindow.xaml` 拆为主页、待办、扩展、设置四个独立视图，减少单文件布局相互影响。
2. 将快捷项选择器、编辑弹窗和删除确认从代码后置中抽成可测试服务或对话组件。
3. 把 `HomeViewModel` 拆为搜索、快捷项、AI 设置、系统设置等子 ViewModel；`TodoViewModel` 再拆为列表、编辑器、AI 草稿和提醒状态，降低千行级类的维护风险。
4. 补齐键盘路径：主页搜索、结果、快捷项菜单、待办筛选、确认卡和设置项应能按视觉顺序 Tab；焦点返回触发控件；快捷键不得与输入法冲突。
5. 以当前浅色主题为基线补充深色/跟随系统和高对比模式；在实现前先建立颜色 token 与对比度测试。

**验收口径**

- 连续切换页面各 20 次无重复实例、选中态错误或焦点丢失。
- 所有主路径可仅用键盘完成，状态变化可被 UI Automation 读取。
- 100%～200% 缩放下没有不可达操作或严重截断。
- 未保存配置不会因显式关闭、页签切换或失焦被静默丢弃。

### 4.3 本地搜索

**当前基础**

- 用户目录按范围写入 SQLite，搜索只匹配名称，不读取文件正文。
- 支持“全部范围、仅应用、单个授权目录”、七类筛选、普通包含匹配、可选通配符和 `re:` 正则。
- 输入有 300ms 防抖，旧查询结果通过取消令牌和 generation 隔离。

**已确认的实现风险**

1. 首次启动仅提示用户手动添加范围，尚未实现 PRD 已确认的“桌面/文档/下载候选目录展示并经用户确认后才读取”。
2. 默认扫描器先把整个目录结果聚合到内存，再进入可取消的批量写入；大目录扫描期间取消不够及时，进度也不能反映真实总进展。
3. 重新索引会清空旧数据后分批插入；中途写入失败可能留下不完整的新索引，需要事务化的临时版本切换。
4. 当前查询以包含匹配和最近修改时间排序为主，尚未实现精确匹配、前缀匹配和类型权重；`LIKE '%关键词%'` 也无法充分利用普通名称索引。
5. 应用入口来自开始菜单和 `App Paths`，但还需要对重复目标、失效入口和显示名冲突进行归一化。

**P0 优化**

1. 落地首次授权卡片：只解析并展示候选路径，用户确认前不枚举文件；支持全选、逐项取消、稍后设置和查看隐私说明。
2. 为每个范围展示“等待、准备中、可用、失败、已取消、路径失效”状态、累计条目和最后更新时间，并提供取消、重试、重新索引、移除动作。
3. 将扫描改成可流式枚举且逐项检查取消令牌；进度报告使用累计数，取消后保留上一份可用索引。
4. 使用 staging 表或索引版本号：完整扫描成功后在单事务中切换，失败时回滚到旧版本，避免部分结果被当作可用范围。
5. 把权限、路径失效、正则错误、打开失败映射为稳定错误码和非技术化提示，不向 UI 拼接原始异常信息。

**P1 优化**

1. 引入按范围的 `FileSystemWatcher` 增量更新，并对事件合并、溢出和目录重命名设置全量重建兜底。
2. 建立可解释相关性排序：完全匹配 > 名称前缀 > 分词/连续子串 > 普通包含，再叠加类型偏好和适度的最近修改权重。
3. 对开始菜单和 `App Paths` 做规范化去重，保留最可启动的目标并显示来源；应用发现失败不影响文件范围搜索。
4. 增加分页或虚拟化，避免固定 100 条结果成为不可解释截断；UI 应显示“已展示前 N 条”并允许继续加载。
5. 用固定 20,000 条匿名元数据集执行不少于 200 次代表性查询，记录 P50/P95、取消耗时、索引耗时和峰值内存。

**验收口径**

- 用户确认前对候选目录零枚举；撤销范围后该范围及缓存命中为 0。
- 取消大目录索引后 UI 在可接受时间内恢复，上一份成功索引仍可查询。
- 任意失败都不会把部分索引标记为 Ready。
- 20,000 条基准下首屏 P95 满足 `≤ 1s`，并保留原始报告和参考机信息。

### 4.4 快捷入口

**当前基础**

- 支持应用、文件和目录选择或拖放添加，重复目标需确认。
- 支持名称、描述、自定义图标、目标重定位、移除和上下排序。
- 目标失效时不自动删除，启动仍沿用当前 Windows 账户权限。

**P0/P1 优化**

1. 在卡片上直接展示失效状态和“重新定位/移除”，避免用户先点击失败后再猜测处理方式。
2. 添加前提供名称、类型、目标和图标预览；批量拖放后分别列出成功、重复、无效和失败项。
3. 增加拖动排序与键盘上移/下移，保留现有菜单作为无障碍兜底。
4. Shell 图标提取改为后台加载、尺寸分级缓存和失败占位，避免大量快捷项首次展示阻塞 UI。
5. 保存新图标或删除快捷项后执行引用计数式清理，移除不再被任何记录引用的图标副本；清理失败不影响快捷项本身。
6. `ShortcutStore.Reorder` 应保留输入列表未包含的合法记录，避免未来并发刷新或版本迁移时意外丢项。

**验收口径**

- 0、1、超过单行上限三种数量下均可访问添加入口和全部快捷项。
- 失效项不崩溃、不自动删除，并始终提供可恢复动作。
- 排序、编辑、图标和重定位重启后保持；移除引用不修改目标文件。
- 图标缓存清理不删除仍被引用的文件，失败可安全重试。

### 4.5 托盘、自启与帮助

**当前基础**

- WinForms `NotifyIcon` 提供桌宠显示/隐藏、工具窗口、设置、自启、帮助和退出。
- 自启写入当前账户 HKCU Run，不静默提权；变更后会重读实际状态。
- 帮助打开安装包内离线 HTML，失败时不跳转未知网址。

**P0 优化**

1. 托盘菜单在每次打开时重读并展示桌宠可见、工具窗可见、自启实际状态；不要只显示固定“显示/收起”文案。
2. 处理 Explorer/任务栏重启后的托盘图标重建，避免应用仍运行但入口消失。
3. 安全退出前取消并等待索引、AI 请求、提醒检查和单实例等待线程；设置 5 秒上限，超时记录非敏感任务类型并继续可控退出。
4. 自启项不仅检查值是否存在，还应校验命令是否指向当前可执行文件和正确参数；升级或移动便携目录后提示修复。
5. 修正用户手册与 0.8.0 行为的漂移。例如当前隐私摘要仍把待办描述为“后续版本”，正式打包前必须同步为已上线的本地功能。
6. 打包测试校验手册版本、文件存在、默认处理程序打开请求和缺失时的修复提示。

**P1 优化**

1. 使用项目正式图标替代 `SystemIcons.Application`，并验证浅色/深色任务栏可辨识度。
2. 实现技术设计中已规划的脱敏诊断导出：仅白名单字段、无 Key、查询原文、完整路径、快捷项描述和待办内容。
3. 在设置页提供“检查自启状态”“打开日志目录”“打开数据目录”等明确诊断动作，避免用户手动猜测路径。

**验收口径**

- Explorer 重启后托盘入口可恢复；菜单状态与真实状态一致。
- 后台任务运行时退出仍在 5 秒内完成且不损坏索引或配置。
- 自启开启、关闭、策略拒绝、安装目录变化四类场景均可解释并回滚。
- 离线手册与当前版本行为一致，缺失时不打开未确认在线地址。

### 4.6 AI 接入配置

**当前基础**

- 提供 DeepSeek 等 8 家内置供应商和一个自定义 OpenAI 兼容入口。
- 供应商切换会填充默认端点与模型，用户仍可覆盖修改。
- 当前配置必须测试通过后才能保存；测试期间修改字段会使结果失效。
- Key 通过 Windows Credential Manager 保存，普通设置不保存 Key 明文。

**P0 优化**

1. 增加明确的“清除 AI 配置”动作：二次确认后删除当前凭据、非敏感连接状态和内存中的 Key，并验证清除后不能继续调用。
2. 供应商切换并保存时处理旧 `SecretTargetName`：提示保留还是删除，默认删除不再使用的旧凭据，避免多个 Provider Key 静默残留。
3. 所有错误只显示标准化类别、时间和建议；移除 UI 中拼接 `Exception.Message` 的路径，禁止响应正文、Header、URL 查询参数和 Key 片段进入日志或界面。
4. 为 401、403、429、400/404、DNS、连接拒绝、超时、5xx 和无效 JSON 建立本地 fake server 集成测试；验证失败不覆盖上一份已保存配置。
5. 明确测试语义：如果 `GET /models` 只能验证鉴权和端点，界面不得声称目标模型已验证；需要验证模型时，按供应商能力选择低成本最小请求并明确可能产生用量。

**P1 优化**

1. 复用受控生命周期的 `HttpClient`，统一连接、总请求和读取超时，并提供用户主动取消。
2. 为预设增加能力描述：Models 接口、Chat Completions 路径、结构化输出能力和官方信息来源；默认值变化只更新元数据，不改变用户已保存值。
3. 端点校验禁止嵌入用户名/密码；远程明文 HTTP 需阻止或明确警告，本机 `localhost` 开发端点可按策略放行。
4. 设置页显示上次验证时间、验证范围、供应商来源和当前配置是否已修改，支持复制不含敏感值的诊断摘要。

**验收口径**

- Key 不出现在设置、日志、错误 UI、测试快照和诊断导出中。
- 清除后 CredMan 与内存中均无可继续使用的凭据。
- 测试失败、取消或期间修改字段均保持输入且保存禁用。
- 同一时刻只有一个连接测试；所有错误类别由 fake 服务可重复触发。

### 4.7 待办与 AI 结构化草稿

**当前基础**

- 手动创建、编辑、完成、恢复、仅取消提醒、删除及日期筛选已实现。
- AI 支持创建、修改、完成、删除和稍后提醒草稿；确认前零写入，同名目标需要选择。
- 模糊、过去时间和服务错误会保留输入并允许重试或转手动。

**P0/P1 优化**

1. 手动表单就地显示字段级错误，明确标题长度、时间格式、提醒必须晚于当前时间，以及提醒与截止时间的关系；不要只显示一段通用错误。
2. 手动删除、完成、恢复和编辑也提供短时撤销，统一 AI 与手动入口的恢复语义；若继续物理删除，撤销快照必须只在内存短期保存且不上传。
3. 列表排序规则固定为提醒时间、截止时间、创建时间的可解释组合，并允许用户看到当前排序，不依赖存储文件顺序。
4. AI 澄清从静态提示升级为受控补充字段或一次补充输入；每轮只携带本次必要上下文，用户可随时清除并转手动。
5. 限制 AI 响应读取大小、JSON 层级、标题/备注长度和 `snoozeMinutes` 边界；支持结构化输出的供应商可优先使用 JSON schema，但本地领域校验始终是最终门槛。
6. 对 AI 生成的修改、删除和完成继续展示唯一目标及变更前后值；确认按钮应明确动作，不使用笼统“确定”。
7. 修正文档和界面中“待办仍是后续功能”的旧文案，统一 0.8.0 的已上线边界与隐私说明。

**验收口径**

- 创建、修改、完成、恢复、取消提醒、稍后提醒和删除互不混淆，重启后状态一致。
- AI 确认前本地列表、文件和调度器均无副作用；确认后只执行一次。
- 同名目标未唯一选择时不能执行；取消和清除不会残留草稿。
- 超大响应、非法枚举、越界时间和冲突字段均被本地拒绝并可转手动。

### 4.8 一次性提醒

**当前基础**

- `ReminderScheduler` 默认每 15 秒检查一次到期待办。
- 应用运行时显示页内提醒并提交托盘气泡；启动或恢复检查可把过期项标记为补发。
- 已投递、取消、失败和已完成事项不会自动重复投递；稍后提醒会重新进入调度。

**P0 优化**

1. 设置页显示通知通道状态和真实运行条件；通知被系统抑制时不得显示“已送达”，页内提醒仍保留可操作入口。
2. 监听系统时间、时区、休眠/恢复事件并立即重算下一次检查；补发、过期和重复去重需要独立测试。
3. 提醒失败后提供“重试通知、仅保留待办、取消提醒”动作；自动重试必须有限次、可去重且不能轰炸。
4. 为每次提醒生成稳定投递标识，将状态更新与投递结果做幂等处理，避免并发检查或快速恢复造成双投递。
5. 在普通交互式 Windows 会话完成专注助手、通知关闭、锁屏、休眠、时区变化、应用重启和托盘点击 E2E。

**P1 优化**

1. 从固定 15 秒轮询改为“下一条提醒到期时间 + 恢复事件”的自适应调度，空列表时不持续唤醒。
2. 评估 Windows App SDK 原生通知，支持“完成、10 分钟后、打开详情”按钮和通知权限查询；迁移前保持页内通道为可靠兜底。
3. 通知历史只保存状态码和延迟区间，不保存标题、备注或具体时间；为送达成功率建立隐私合规口径。

**验收口径**

- 同一提醒在正常、恢复和并发检查中最多投递一次。
- 休眠/时区变化后按冻结规则补发或标记错过，不静默改动截止时间。
- 通知失败不记成功，用户可见原因和恢复动作。
- 空列表时调度器无固定高频轮询；新增/修改提醒后能及时重排。

### 4.9 数据、隐私与诊断

**当前基础**

- `settings.json`、`layout.json`、`shortcuts.json` 和 `todos.json` 使用可恢复原子写入。
- 损坏 JSON 会回退默认值或空列表，原损坏文件不会被新默认值直接覆盖。
- 搜索索引、普通设置、日志和凭据存储已分离。

**P0 优化**

1. 为所有持久化文档建立显式 schema 版本和迁移器；迁移过程先备份、成功后提交，失败回滚并给出恢复提示。
2. 损坏文件不应只静默回退：保留原文件、生成脱敏诊断码，并在设置页提供“重试读取、导出副本、恢复最近备份、重置该模块”。
3. 统一数据目录策略和删除边界，明确卸载默认保留什么、“清除本地数据”会删除什么、凭据是否单独确认。
4. 增加自动敏感信息扫描，覆盖普通配置、日志、异常 UI、诊断包和测试快照；关键字扫描之外还要使用测试哨兵值验证完整链路。

**P1 优化**

1. 统一 `ISettingsRepository`/模块存储接口，集中处理锁、原子写入、迁移、备份和错误分类。
2. 实现白名单诊断导出和本地数据清单预览，用户确认后再生成压缩包。
3. 为索引、图标缓存、日志和备份增加大小/保留策略，清理操作必须可失败重试且不碰用户目标文件。

**验收口径**

- 从每个历史 schema 升级到当前版本都有自动化测试；中断迁移后仍能读取旧版本。
- 损坏数据不会覆盖最近可用副本，也不会让应用无提示地长期运行在默认状态。
- 一键清理前展示范围；清理后 Key、配置、待办、缓存和日志按用户选择准确处理。

### 4.10 工程结构、测试与发布

**当前问题**

1. `HomeViewModel.cs`、`TodoViewModel.cs`、`PetToolWindow.xaml.cs`、`PetWindow.xaml.cs` 和 `App.xaml.cs` 均承担较多职责，继续叠加功能会显著提高回归成本。
2. 统一测试入口曾递归查找第一个 `.sln`，当前工作区存在 `build/github-sync-*` 时会误测旧副本；该问题已在 0.8.1 固定为直接运行当前 `src/AiPet.sln`，并由回归输出核对 138 项测试。后续若新增解决方案，仍需保持显式路径与版本校验。
3. 现有门禁未实际执行 `dotnet format --verify-no-changes`、静态分析、覆盖率、安全扫描、独立集成测试、系统 E2E 和打包烟雾的完整组合，与 `TEST_PLAN.md` 中的目标契约仍有差距。
4. 发布目录保留多个历史版本时，打包脚本必须防止旧资产、旧校验和或旧 staging 被误选进当前 Release。

**P0 优化**

1. `scripts/test.ps1` 已固定使用 `src/AiPet.sln`，输出被测 solution 的规范化路径、当前版本和实际测试总数；新增测试工程时继续拒绝 `build/`、`dist/` 和所有缓存目录中的副本。
2. 在测试开始前检查工作树中的源码与被测路径一致，拒绝从复制目录或旧发布 staging 运行主门禁。
3. 建立 `tests/integration/`：真实临时 SQLite、原子写入中断、schema 迁移、fake HTTP、CredMan 测试账户和隐私哨兵扫描。
4. 建立 `tests/e2e/`：宠物/工具窗、搜索范围、快捷项、设置、托盘、自启、帮助、待办、提醒与退出主路径；环境受限项必须明确报告未运行。
5. 固化交互式发布烟雾清单：便携运行、全新安装、覆盖升级、启动、凭据、通知、休眠恢复、自启、帮助、卸载和配置保留。
6. 打包前清空或使用唯一 `build/<version>/<run-id>/` staging，只把当前 `VERSION` 的两个资产写入本次清单；SHA-256 必须从最终文件重新计算。

**P1 优化**

1. 加入格式、编译告警、依赖漏洞、许可证和覆盖率报告；关键安全与状态逻辑使用分支覆盖目标，不能只看总覆盖率。
2. 为搜索性能、工具窗唤出、空闲资源和提醒延迟建立可重复基准，报告参考机、数据集、运行次数和 P50/P95。
3. 引入模块级接口和依赖注入，统一取消、释放和异常边界；后台任务由应用生命周期集中管理。
4. 把文档一致性加入校验：版本、已上线功能、手册、PRD、测试数量和发布说明不得相互矛盾。

**验收口径**

- 统一测试入口与直接运行当前 solution 的测试总数和结果一致。
- 集成/E2E/性能/安全各层分别报告通过、失败、跳过和不适用。
- 发布脚本无法误用旧版本资产，清单只包含当前版本且哈希匹配。
- 正式发布前满足 `PROJECT_SPEC.md` 与根 `AGENTS.md` 的完整完成定义。

## 8. 每项优化的完成定义

单项优化只有同时满足以下条件才可标记完成：

1. 关联到明确的 PRD 编号、风险或本文件 `OPT-*` 条目。
2. 实现范围、异常边界、隐私影响和数据迁移已说明。
3. 新增或修改行为有自动化测试；系统相关行为有可重复的交互式验证记录。
4. `scripts/test.ps1 -CI` 确认运行的是当前 `src/AiPet.sln`，且所有已配置测试通过。
5. PRD、技术设计、用户手册、测试计划、README 与变更日志按行为同步。
6. 按 SemVer 选择最小准确版本，并通过统一脚本更新版本元数据。
7. 面向发布的变更重新生成便携版、安装版和 SHA-256，完成安装、运行、升级、卸载和便携烟雾。
8. Git、标签和 GitHub Release 门禁全部完成前，只能称为发布候选，不能称为正式发布。
