# Windows AI Desktop Pet 0.16.0 候选说明

日期：2026-09-09。0.15.0 → 0.16.0 是向后兼容的功能扩展 MINOR。当前为候选版本；完整发布门禁尚未全部通过，没有创建 `v0.16.0` 标签或 GitHub Release。

## 新增

- 待办筛选从四种扩展为六种：新增“已逾期”和“未安排”，“今天”也识别已确认时间块的开始时间。
- 待办页新增“今日安排”。用户逐项勾选 1～12 条待处理事项后，可使用当前 AI 配置生成当天时间块。
- AI 请求只包含明确勾选项的 ID、标题、备注、截止时间以及当前时间/时区；未勾选和已完成事项不进入请求。
- 提供完全本地的安排方式，按截止优先排序，从下一刻钟开始为每项分配 30 分钟，不依赖 AI 或网络。
- 草稿展示每项开始/结束与理由，可逐项取消。确认项一次原子写入，最近一批可以整体撤销。

## 安全与一致性

AI 返回必须完整覆盖选中 ID，且不得包含额外或重复 ID。所有时间必须为带偏移的 ISO 8601 绝对时间，位于本地今天且晚于当前时间；单项 15 分钟至 4 小时，时间块不得重叠。任何一项失败都不形成可写草稿。

批量确认在 TodoStore 锁内重新核对每项 `UpdatedAt`，先验证全部候选再写一次文件。草稿生成后任何选中待办发生修改，整批拒绝，不用旧结果覆盖新内容。批量撤销同样核对确认后的时间戳。

明确选择卸载并清理个人数据时，清理固定 GitHub 更新令牌和设置迁移 `.pre-v5.bak`，避免凭据或旧设置副本遗留。

## 升级说明

`todos.json` 从 schema 3 升到 4，新增可空 `plannedStartAt`；安排块结束继续使用 `dueAt`。首次读取旧数据会保留 `.pre-v4.bak`，既有待办、提醒、重复规则和通知队列不变。手动或单项 AI 修改截止时间时，旧计划开始时间会清除，避免显示不一致的时间块。

## 验证边界

完整自动化 278/278、今日安排定向测试 9/9 通过；干净输入打包和便携/安装/启动/卸载烟雾测试通过。独立 UI 与窗口性能测试因当前桌面不能把应用置前而在输入前失败；真实 Provider 的今日安排请求、真实鼠标键盘选择与确认仍需独立见证。签名和物理设备的最终结果见[0.16.0 验证报告](release/0.16.0-test-report.md)；没有证据时不得写为 PASS。
