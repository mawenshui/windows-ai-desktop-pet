## 1. 版本决策

0.26.0 交付一个边界明确的扩展点：**安全的本地 2D 角色包库**。用户可以选择本机中已经解压的角色包文件夹，在应用展示清单、许可、作者、角色数、帧数、解码预算和内容指纹后明确确认导入；导入成功后，包内角色进入现有设置页的角色列表，可即时切换、查看本地许可或移除。

本版不提供在线下载、商城、支付、账号、广告、云同步、评分、自动更新、创作者分成、商业角色 DLC、3D、音频、通用插件或任何可执行代码扩展。角色包是纯本地声明式资源，不获得搜索、网络、进程、注册表、凭据或任意文件访问能力。

该选择延续 0.25.0 的产品路径：桌宠仍是主体，角色内容扩展只出现在设置页“桌宠形象”区域，不新增主页面，也不把工具窗改造成内容商店。

## 2. 目标与非目标

### 2.1 产品目标

- 用户可在不修改安装目录的前提下，把符合规范的本地 2D 角色包导入当前 Windows 账户。
- 导入前必须看见稳定、可核对的包摘要；确认前不写入应用数据目录。
- 角色切换继续遵循“先验证、再保存、再应用；失败回滚”的既有语义。
- 外部包损坏、被手工修改或版本不受支持时，应用自动回退到内置 RGS `hero`，不出现空白桌宠或启动崩溃。
- 内置 RGS 包永远可用、不可移除，是所有异常路径的安全回退。
- 导入包纳入手动备份、每日自动备份、恢复事务和卸载个人数据清理。

### 2.2 明确非目标

- 不接收 ZIP、RAR、7z 等归档；用户选择已经解压且根目录含 `pet.json` 的文件夹。归档解析留待独立安全评估。
- 不访问 `source.url`，不替用户下载许可、素材或更新。
- 不审核作品权属，不把 SPDX 字段等同于法律授权；界面持续提示“导入者仍需确认素材权利”。
- 不支持任意动作名、任意状态机、脚本、着色器、字体、SVG、GIF、WebP、视频、音频、模型或网络资源。
- 不提供角色包编辑器、精灵图切分、在线分享、订阅、付费或推荐算法。
- 不改变现有搜索、AI、待办、提醒、专注和复盘的数据范围。

## 4. 角色包合同

### 4.1 根目录

```text
<selected-folder>/
├─ pet.json
├─ SOURCE.txt
├─ License.txt
└─ frames/
   ├─ <character>/
   │  ├─ idle_<direction>_<NN>.png
   │  └─ jump_<direction>_<NN>.png
   └─ _global/
      └─ death_<NN>.png              # 可选，由 manifest 声明
```

导入器不递归复制其他文件。缩略图直接使用首选角色的 `idle_down_01.png`，不引入单独封面协议。

### 4.2 身份和来源

- `id`：`^[a-z0-9][a-z0-9-]{0,63}$`，不得等于内置 `rgs-8dir`。
- `displayName`：去除首尾空白后 1～100 个字符。
- `version`：三段 SemVer 数字，不接受预发布后缀。
- `source.author`：必填，最多 100 个字符。
- `source.url`：必填 HTTPS URL；仅展示，不主动访问。
- `source.license`：只允许 `CC0-1.0`、`CC-BY-4.0`、`CC-BY-SA-4.0`、`MIT`、`Apache-2.0`。
- `source.zipSha256`：64 位十六进制来源归档摘要；`SOURCE.txt` 必须同时包含该摘要和 SPDX 标识。
- `License.txt`：20 字节～256 KiB，只作为本地许可原文打开，不解析其中法律条款。

### 4.3 动画与方向

- 每包 1～16 个角色；角色 token 使用 `^[a-z][a-z0-9_]{0,31}$` 且唯一。
- 角色动作固定为 `idle` 与 `jump`，不能声明任意动作执行逻辑。
- 原绘方向固定为 `down`、`down_right`、`right`、`up_right`、`up`；其余三个方向继续由运行时镜像。
- 每个动作 1～60 帧；`idle` 和 `jump` 都必须存在。
- 全局动作只能是可选 `death`，1～60 帧；应用继续按内置语义触发，不执行 manifest 中的任意事件表达式。
- `filePathPattern` 和 `deathFilePathPattern` 必须与现有固定模板精确一致。
- `render.fps` 为 1～30；`defaultScale` 为 0.25～4。锚点和状态机字段只作为兼容元数据读取，不改变当前受控运行时行为。

### 4.4 文件与资源预算

| 约束 | 上限 |
| :--- | :--- |
| manifest / `SOURCE.txt` | 各 64 KiB |
| `License.txt` | 256 KiB |
| 单张 PNG | 4 MiB、512×512 |
| 总声明帧 | 1,000 |
| 总编码文件 | 32 MiB |
| 总解码估算 | 128 MiB RGBA |
| 导入文件数 | 1,003（含三份元数据） |

校验先检查 PNG 签名和 IHDR 尺寸，再用 WPF 解码器实际解码单帧像素。路径必须是规范化后的包内相对路径；任何绝对路径、驱动器、ADS、`.`、`..`、空路径段、符号链接或 Windows 重解析点均拒绝。

## 5. 数据与事务

### 5.1 存储位置

外部包保存到：

```text
%APPDATA%/WindowsAiDesktopPet/pet-packs/<pack-id>/
```

导入 staging 位于同一 `pet-packs` 根目录的 `.staging-<guid>`，保证最终目录移动不跨卷。应用只根据目录名和重新校验后的 manifest 建立角色库，不信任缓存清单。

### 5.2 设置 schema 7

继续复用 `pet.id` 和 `pet.preferredCharacter`：

```json
{
  "schemaVersion": 7,
  "pet": {
    "id": "my-local-pack",
    "preferredCharacter": "companion"
  }
}
```

schema 6 及更早版本原本已把 `pet.id` 保存为 `rgs-8dir`，迁移时不需要猜测外部目录，只升级 schema 并保留当前角色。升级前生成 `.pre-v7.bak`。

### 5.3 导入事务

1. 用户选择文件夹。
2. `Preview` 完成全部格式、许可、路径、图像和预算校验，计算按规范相对路径排序的 SHA-256 内容指纹。
3. UI 展示预览；此时应用数据目录不产生目标包。
4. 用户点击“确认导入”。
5. 再次校验源目录，要求 ID 与指纹等于预览值。
6. 只复制白名单文件到 staging；复制后再次完整校验并比对指纹。
7. staging 原子移动为 `<pack-id>`；重复 ID 拒绝覆盖。
8. 刷新角色列表，但不自动切换当前角色。

任何失败都删除本次 staging；已导入包、当前角色和设置保持不变。导入源目录永不修改。

### 5.4 切换和移除事务

切换时先验证目标包和角色首帧，再保存设置，再通知运行时替换帧缓存。运行时替换失败时，ViewModel 恢复旧设置，`PetWindow` 恢复旧缓存和当前帧。

移除只针对当前选中的外部包，并采用页内两步确认：

1. 显示包名及“将先切回内置红帽勇者；不会删除原始导入文件夹”。
2. 成功保存并应用 `rgs-8dir/hero`。
3. 删除应用数据目录中的外部包。
4. 刷新角色库并公布结果。

切回失败时不删除。切回成功但删除失败时保持内置角色，外部包仍留在库中，用户可重试。

### 5.5 启动回退

启动先校验内置包，再逐个扫描外部包。外部包之间相互隔离；一个包损坏不阻止其他包加载。若设置指向缺失、损坏或不含指定角色的外部包，应用使用内置 `rgs-8dir/hero`，尝试保存回退设置并显示稳定状态。内置包本身损坏仍按现有不可恢复启动错误处理。

## 6. 界面设计

设计延续奶油米白、暖橙焦点和既有 `SectionCard` / `InlineChoiceList`，不新增颜色、字体、动画或页面。

### 6.1 角色库

- 标题改为“桌宠角色库”，说明“内置角色始终保留；本地包只在确认后复制”。
- 角色列表继续使用原生单选 `ListBox` 和两列卡片。每张卡固定显示 64×64 正面首帧、角色名、包名与 SPDX；选中状态同时使用文字“已选”、字重和暖橙色。
- 列表下方只有一个“当前选择”操作带，提供“查看本地许可”和外部包的“移除当前包”；不在每张卡重复堆叠按钮。
- 导入入口是带文字的次按钮“从本地文件夹导入”，不使用无标签图标。

### 6.2 导入预览

选择文件夹并校验成功后，在角色列表下方显示一块渐进披露预览：

- 包名、作者、SPDX；
- `N 个角色 · N 帧 · 预计解码 N MiB`；
- 指纹前 12 位；
- 固定提示“应用未验证素材权属；请确认你有权使用和再分发”；
- 主操作“确认导入”和次操作“取消”。

校验错误在同一区域用稳定类别和下一步说明，不显示堆栈或完整源路径。导入运行期间保留按钮文字并阻止重复提交。

### 6.3 键盘与可访问性

- 角色列表保留方向键、Home/End 和原生单选语义；卡片自动化名称包含角色名、包名、许可和选中状态。
- 导入、许可、移除、确认与取消均可 Tab 到达，焦点样式复用现有资源。
- 动态预览、错误、导入和回退结果使用 polite live region；状态不只靠颜色。
- 页内确认出现时，焦点进入“继续保留/移除角色包”按钮区；Esc 先取消页内确认，再执行工具窗既有收起语义。
- 200% 缩放时使用现有纵向滚动，角色卡内容换行且不裁切；不依赖 hover 才能发现操作。

## 8. 安全与隐私

- 角色包没有代码执行入口；manifest 的未知顶层字段直接拒绝，状态机不作为通用解释器运行。
- `source.url` 只显示，不请求；导入流程完全离线。
- 默认日志只记录稳定类别，不记录导入源路径、包内容、用户名或指纹全文。
- 指纹用于复制前后完整性复核，不是签名、作者身份或权属证明。
- 导入文件存在用户账户的数据目录；卸载保留/清理继续由用户选择。
- 备份包含用户主动导入的素材及其许可文件，因此用户需要自行确认对备份和迁移副本的使用权。
- 商业 IP、官方立绘和“可浏览但不可再分发”素材不得作为项目内置或 Release 资产；本功能不改变仓库资产许可门禁。

## 9. 实现顺序

必须按以下顺序推进，前一阶段的自动化测试通过后再进入下一阶段：

1. **合同与校验**：把 `EXT-08` 原型收敛为正式 `AiPet.Pet` 代码；增加 `License.txt`、固定动作、错误分类和预算测试。
2. **本地库事务**：实现预览、staging 导入、重复拒绝、复制后复核、枚举与移除；删除原型中的重复产品候选代码。
3. **设置与维护**：schema 7、`.pre-v7.bak`、`PetPacks` 备份/恢复依赖及卸载清理测试。
4. **运行时切换**：App 按包和角色解析，`PetWindow` 原子替换帧缓存；启动损坏回退并持久化。
5. **设置页体验**：动态角色卡、来源/许可、导入预览、确认和移除操作带；完成键盘、UI Automation、200% 缩放静态回归。
6. **文档与门禁**：同步 PRD、技术设计、用户手册、测试计划、README、状态、变更日志和版本计划；首轮完整测试通过后升级到 0.26.0，再复测、打包和 smoke。

## 10. 测试矩阵

### 10.1 单元与集成

- 合法 RGS 副本可预览，帧数、预算和指纹稳定。
- 未知字段、非法 ID/版本/URL/SPDX/来源摘要、缺文件、固定模板变化、重复 token、错误动作/方向、帧数不符均拒绝。
- PNG 签名、IHDR、真实解码、单文件/总编码/总解码预算均覆盖边界。
- 绝对路径、`..`、ADS、链接/重解析点和大小写重复目标拒绝。
- 预览后源文件变化、复制中变化、重复 ID 和 staging 残留均不会产生半导入。
- 有效包枚举、无效包隔离、活动包损坏回退、移除不修改源目录。
- schema 6 → 7 保留 `rgs-8dir` 与角色，生成 `.pre-v7.bak`；无效包/角色规范化由 App 回退，不由设置层猜测。
- `PetPacks` 与设置共同备份/恢复，恶意归档路径仍在写入前拒绝。
- ViewModel 切换成功、保存失败、运行时失败回滚、预览取消、确认导入和移除确认均覆盖。

### 10.2 UI、smoke 与可选诊断

- XAML 静态检查确认原生列表、可见标签、live region、确认文案和至少 36 DIP 紧凑操作目标。
- 应用 smoke 使用仅内置包启动；另以隔离数据根验证外部包设置损坏时回退并继续运行。
- 独立 UI 自动化若当前环境不能安全置前，记录 SKIP/FAIL 的真实原因，不推断通过；不阻断正式发布。
- 性能、签名、多屏/缩放和物理环境继续按仓库规则作为可选诊断。
