# 0.19.0－交互与功能完善设计

> 状态：设计冻结并已按顺序实现，候选验证中。基线为 0.18.1；本版属于向后兼容的可见功能扩展，已按 MINOR 升级到 0.19.0。

## 1. 背景与现状审计

0.18.1 已具备桌宠、四页工具窗、搜索、快捷入口、待办提醒、维护、设置、AI 配置和更新检查，但日常操作仍存在以下可复现的体验缺口：

| 编号 | 现状证据 | 用户影响 | 本版处理 |
| :--- | :--- | :--- | :--- |
| A-01 | 主页的快捷入口区和所选搜索结果操作区都位于主网格第 5 行 | 选中结果后两个区域可能重叠，按钮和快捷入口难以辨认或点击 | 拆分为独立网格行，并保证搜索结果仍获得剩余空间 |
| A-02 | 标题栏三个图标按钮为 28×28；快捷卡管理按钮为 18×18 且默认透明 | 命中区偏小，逐项管理主要依赖悬停发现 | 扩大命中区，管理入口在静止状态也可发现 |
| A-03 | 失效快捷入口主要用红点表达 | 状态依赖颜色，键盘及低视力用户难以判断原因 | 改为图形与文字/自动化名称共同表达 |
| A-04 | 搜索框与结果列表之间缺少直接键盘移动路径 | 输入后需要多次 Tab 或鼠标才能进入结果 | `Down` 进入首条结果，`Up` 从首条结果回到搜索框 |
| A-05 | 待办页首先展示 AI、提醒中心和今日安排，手动新建与清单位于后方 | AI 可选能力压过手动核心任务，常用清单需要滚动才能看到 | 手动清单与新建优先；AI、今日安排作为可展开的渐进能力 |
| A-06 | 设置页很长，外观、快捷键、更新、搜索和 AI 只能连续滚动定位 | 低频设置可收纳，但重新进入目标区成本偏高 | 增加页内设置目录，选择后滚动到对应分组并移动焦点 |
| A-07 | 维护页的缓存清理与普通次要按钮视觉接近 | 可恢复与需重启操作的风险层级不够明确 | 增加克制的危险次要按钮及明确后果文案 |
| A-08 | 页面切换仅提供鼠标、Tab 和 `Ctrl+Tab` | 键盘用户在四页间跳转仍需循环操作 | 增加 `Alt+1`～`Alt+4`，保留 AI 未保存修改保护 |

## 2. 设计目标与原则

### 2.1 目标

1. 修复主页区域覆盖，确保 360～440 DIP 宽度与受限工作区高度下仍可完成搜索主路径。
2. 让每个高频动作在鼠标与键盘下都可发现、可执行、可恢复。
3. 让手动待办成为待办页主路径，AI 和今日安排保持可见但渐进披露。
4. 让设置页可以一步定位到目标分组，且不绕过 AI 未保存编辑保护。
5. 统一按钮、状态、危险操作和焦点反馈，同时保持桌宠优先的紧凑形态。

### 2.2 原则

- 宠物优先：不增加独立主窗口，不把工具气泡改造成传统侧栏后台。
- 一击即达：搜索、快捷入口和新建待办保持首屏可达。
- 本地可信：不改变搜索授权、凭据、备份、日志或 AI 发送边界。
- 渐进披露：AI、重复规则、迁移、代理等低频或高级能力可展开，不抢占主路径。
- 状态可解释：禁用、失败、失效、选中、处理中不能只靠颜色表达。
- 键盘等价：鼠标可完成的高频路径必须有清晰键盘路径和可见焦点。

## 3. 信息架构与布局

### 3.1 工具窗外壳

- 保持 440×536 DIP 基准和宠物锚定定位，不开放自由缩放。
- 四页顺序保持“主页、待办、维护、设置”，不改变托盘及定向唤出语义。
- 标题栏状态按钮使用 36×36 DIP 命中区；图标仍使用现有 Path，不引入新图标依赖。
- 页签保留页内可见选中标记；新增 `Alt+1`～`Alt+4` 快速跳转，页面切换继续统一经过 `TrySelectTab`。

### 3.2 主页

主页纵向顺序固定为：

1. 搜索范围与搜索框；
2. 首次授权卡片（仅需要时）；
3. 结果类别；
4. 搜索结果（占用剩余高度）；
5. 所选结果操作区（仅选择后）；
6. 快捷入口；
7. 当前状态与继续加载。

所选结果操作区与快捷入口不得共享网格单元。受限高度下优先保留搜索框、类别、至少一条结果和状态行；快捷入口自身滚动，不挤占结果列表的全部空间。

### 3.3 待办页

待办页顺序固定为：

1. “待办清单”标题、新建按钮和六种筛选；
2. 已打开的手动编辑器；
3. 待办列表或空状态；
4. “一句话安排”可展开区；
5. 提醒中心与到达提醒；
6. “今日安排”可展开区；
7. 页面状态与最近一次撤销。

AI 输入和今日安排默认折叠；当收到定向 AI 草稿、已有草稿/错误或用户主动展开时保持展开。折叠只改变视图，不清除输入、草稿、选择或错误。

### 3.4 设置页

设置顶部增加五项页内目录：外观、快捷键、更新、搜索、AI。目录使用可见单选语义，不使用独立 Popup。选择后：

1. 对应分组滚动到视口顶部附近；
2. 焦点移动到分组容器或首个可操作控件；
3. UI Automation 读出分组名称；
4. AI 分组自动展开；离开 AI 分组或设置页仍执行未保存修改保护。

### 3.5 维护页

- 备份为主操作，恢复、诊断为次要操作。
- 缓存清理使用危险次要样式，正常状态不使用高饱和填充。
- 确认文案明确“退出、重启后重建、不会删除设置/待办/快捷入口/凭据”。

## 4. 组件与视觉规范

沿用 `.ui-craft/tokens.md` 和 `ToolWindowTheme.xaml` 的奶油米白、暖橙、Microsoft YaHei UI 与既有圆角。新增或调整的组件如下：

| 组件 | 规范 |
| :--- | :--- |
| 标题栏图标按钮 | 36×36 DIP 命中区，14×14 图标；hover、pressed、focus、checked 均有非布局反馈 |
| 紧凑文字按钮 | 最低 36 DIP；仅用于结果行、列表行和紧凑操作组，主要提交仍保持 44 DIP |
| 危险次要按钮 | 白底、错误色文字与边框；hover 使用极浅错误底色；只用于删除/清理等动作 |
| 快捷入口卡 | 48×48 卡片不变；逐项管理按钮至少 24×24 且静止可见；失效状态含警示图形和可访问文字 |
| 渐进披露卡 | 标题、简短说明、展开状态；折叠时不销毁业务状态 |
| 设置目录 | 五项可见单选，支持方向键；选中含底线、字重和颜色三重反馈 |
| 状态文本 | 成功、错误、处理中保留文字；动态更新使用 polite live region，不依赖 Toast |

动效强度为 3/10：不增加页面入场、弹性或滚动动画；保留现有 hover 轻抬升，并继续服从 Windows 动画偏好和高对比度模式。

## 5. 交互与状态细节

### 5.1 搜索键盘路径

- 搜索框有内容时 `Esc` 先清空搜索；为空时 `Esc` 收起工具窗。
- 搜索框按 `Down`：若有结果，选择并聚焦首条；无结果时焦点不变，并保留当前状态提示。
- 结果列表首条按 `Up`：焦点回到搜索框，查询与选择不变。
- 结果列表按 `Enter`：执行打开；动作前继续重查目标。
- `Ctrl+L`：从任意页返回主页并聚焦搜索框；若从设置 AI 编辑离开，先走未保存保护。

### 5.2 快捷入口

- 卡片主区域仍负责启动，管理按钮只打开现有安全菜单。
- 失效项继续保留，不自动删除；状态由警示图形、工具提示和自动化名称共同表达。
- 管理按钮、右键菜单和管理器窗口保持等价；删除继续进入预览/确认，不删除原目标。

### 5.3 待办渐进披露

- “新建待办”始终是待办页唯一首要动作。
- 手动编辑器打开时，将焦点移到标题；保存成功后焦点返回“新建待办”或相应条目。
- AI 解析中、需澄清、有草稿或有错误时不允许自动折叠 AI 区域。
- 今日安排有草稿或错误时不允许自动折叠；确认/取消后保留用户当前展开选择。

### 5.4 设置定位

- 目录选择属于视图导航，不写入 settings schema。
- 选择 AI 时只展开 UI，不测试连接、不发送请求、不读取未保存 Key。
- 从 AI 区跳转到其他设置分组时，若存在未保存修改，提供“保存、放弃、取消”原有保护；取消后保持 AI 目录选中和原焦点附近。

### 5.5 页面快捷键

| 快捷键 | 结果 |
| :--- | :--- |
| `Alt+1` | 主页并聚焦搜索 |
| `Alt+2` | 待办页并聚焦“新建待办” |
| `Alt+3` | 维护页首个主要操作 |
| `Alt+4` | 设置页目录 |
| `Ctrl+L` | 从任意页返回搜索 |
| `Ctrl+Tab` / `Ctrl+Shift+Tab` | 保留原循环切页 |
| `Esc` | 先处理当前可取消的轻量状态，再按既有规则收起 |

## 6. 实施顺序

### UX-190-01 外壳、令牌与主页结构（P0）

1. 增加紧凑按钮、危险次要按钮和较大标题栏按钮样式。
2. 拆分主页网格行，消除结果操作区与快捷入口覆盖。
3. 调整状态行、快捷区和结果区的最小/最大高度。
4. 为布局结构、按钮命中区和 XAML 可访问属性增加测试。

### UX-190-02 搜索与快捷入口连续操作（P0）

1. 实现搜索框 `Down`、结果首条 `Up`、搜索内优先 `Esc` 和 `Ctrl+L`。
2. 让快捷项管理入口静止可见并扩大命中区。
3. 为失效快捷项增加非颜色状态线索。
4. 覆盖查询保留、选择恢复、打开与管理路径回归。

### UX-190-03 待办主路径与渐进披露（P0）

1. 把清单、新建、筛选和手动编辑移到待办页前部。
2. 将 AI 输入和今日安排改为保留状态的可展开区。
3. 补齐编辑器打开/保存/取消后的焦点恢复。
4. 覆盖折叠不丢状态、标题即时可保存和键盘焦点回归。

### UX-190-04 设置页内目录（P0）

1. 新增五项目录和分组锚点。
2. 实现滚动、焦点、AI 自动展开和未保存保护。
3. 保持 settings schema 5、凭据存储和现有保存基线不变。
4. 覆盖鼠标、方向键、取消保护和重复选择。

### UX-190-05 维护风险层级与反馈（P1）

1. 应用危险次要按钮样式。
2. 统一清理/恢复确认按钮的动词和后果说明。
3. 保持维护事务、重启恢复和数据白名单不变。

### UX-190-06 全局可访问性与快捷键（P0）

1. 实现 `Alt+1`～`Alt+4` 和 `Ctrl+L`，全部复用 `TrySelectTab`。
2. 核对可访问名称、焦点顺序、选中非颜色线索和 live region。
3. 在 360 与 440 DIP 宽度、受限高度及 Windows 动画关闭条件下检查主路径。

### UX-190-07 回归、文档、版本与候选交付（P0）

1. 更新 PRD、工程规范、技术设计、用户手册、离线 HTML、测试计划、README、CHANGELOG、当前状态和设计记忆。
2. 先运行完整测试，再使用 `scripts/bump-version.ps1 -Part Minor` 升级到 0.19.0，并再次运行完整测试。
3. 生成便携版、安装版和 SHA-256；执行当前环境可完成的 UI、性能、安装、启动、卸载与便携烟雾测试。
4. 签名、物理多屏/缩放、休眠/时区和远端 GitHub 资产按实际证据记录 PASS、FAIL 或 SKIP；未满足全部门禁时仅声明候选工作区。

## 7. 数据、权限与兼容性

- 设置 schema 保持 5，待办 schema 保持 4，快捷入口 schema 保持 1，备份格式保持 v2。
- 不新增外部依赖、网络端点、系统权限、日志字段或遥测。
- 不改变搜索授权范围、正文限制、AI 输入边界、Credential Manager 或更新校验流程。
- 0.18.1 数据可直接读取；本版不需要迁移脚本。

## 9. 明确不在本版实施

- 新页面、自由调整工具窗大小、云同步、账号或团队协作。
- OCR、Office/PDF 解析、语义检索、文件预览或文件编辑。
- 通用 AI 聊天、自动执行文件操作、外部宠物包或新角色素材。
- 新 UI 框架、第三方字体、在线图标库、动画库或设计依赖。
- 未经本次真实证据的正式发布、代码签名或物理多屏结论。
