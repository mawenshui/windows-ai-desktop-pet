## 2. 启动、窗口与退出

先获取单实例，再查资源；设置加载前 ApplyPending/RecoverInterrupted，在 SQLite、TodoStore 和窗口工作线程启动前完成恢复或缓存重建。维护失败不继续构造后台服务。App 通过 Attach 注入 XAML 创建的 HomeVM。

工具窗基准 440×536，按工作区空间调整，常驻与置顶独立。页内离散选择继续使用可见 ListBox，不创建独立 Popup。主页把结果操作、快捷入口和状态拆为独立网格行；标题栏控制使用 36×36 DIP 命中区，快捷卡管理入口使用静止可见的 24×24 区域。`TrySelectTab` 统一鼠标、`Ctrl+Tab`、`Alt+1`～`Alt+4`、`Ctrl+L` 和提醒定向入口的 AI 未保存保护；取消停留原页。切页后焦点进入搜索、新建待办、维护主操作或设置目录。文件维护和管理对话框抑制失焦收起。

查询在后台执行并保存代次及索引 Revision，分页遇到变更重新查询。提醒调度使用一次性 Timer，空队列无限等待；TodoStore.Changed、TimeChanged、Resume 重新安排唤醒。SemaphoreSlim 防重入，退出取消任务并有限等待调度完成。通知 UI 每 5 秒处理，避免在每条调度回调中竞争气泡。

`--preview` / `--ui-e2e` 只是在测试进程中使用可自动化的非透明宿主及匿名草稿探针，明确跳过全局快捷键注册和自动备份写入；它不是产品版本、安装包或发布通道。探针不替代真实鼠标键盘输入；正式透明窗、多屏、系统级快捷键和托盘必须独立验收。

待办页先以可见 ListBox 在“清单 / 复盘”二级视图间切换，默认清单且不新增第五个主页面。清单视觉顺序固定为新建/筛选/查找/排序、手动编辑器、专注陪伴、原生单选清单与统一操作带、可选 AI、提醒、今日安排和状态。“专注陪伴”在活动、结果或提前结束确认时自动展开，其他 Expander 保留既有草稿/错误触发逻辑。设置页五项目录只保存当前视图选择，不进入 settings schema；角色和低打扰设置采用明确文本、真实首帧和显式保存，离开时仍调用原未保存修改决策。

## 3. 搜索与索引

授权目录始终索引名称、路径、类型、大小和修改时间；应用入口来自开始菜单/App Paths。受控正文索引默认关闭，只能在设置中单独开启，并复用同一授权范围。`ContentSearchPolicy` 只接受 `.txt`/`.md`，单文件 128 KiB、每范围 1,000 个正文文件和 16 MiB；严格 UTF-8 或带 BOM 的 UTF-16，拒绝 NUL、非法编码、隐藏/系统/重解析点和越界路径。正文存在 SQLite `content_items`，`secure_delete=ON`，不进入普通备份。

每范围 RangeJob 持有 lifetime token、串行锁、待变路径集合和溢出标志。名称和正文全量重建分别写入 `staged_items` 与 `staged_content_items`，提交前检查授权、任务身份、正文开关代次及取消；失败和取消不提交半成品。停用正文搜索会清空正文、正文暂存和统计表并推进代次，旧任务即使继续扫描也不能再次暂存或提交；撤销范围先取消任务，再在一个范围删除事务中清除名称、正文、统计和偏好。启动恢复 watcher；目录变更按子树替换名称与正文，超过 2,048 个排队路径或 watcher 溢出合并为一次全量重建。

元数据扫描约束授权边界并拒绝重解析点。失败/取消保留上一份成功数据，状态记录稳定错误码。取消每个扫描批次、路径和查询循环均可观察；底层文件系统调用不能保证即时中断。

名称或相对路径匹配支持普通文字及可选 wildcard/regex。普通文字在正文开关开启时增加正文包含条件；通配符和正则不查询正文。元数据完全、前缀、包含分值高于仅正文命中，正文结果返回“正文连续包含”和最多 120 字符的折叠空白摘要。固定优先；最近使用排序默认关，主动确认才记录路径/时间。search_preferences 以范围和完整路径为键，撤销范围时删除，清历史保留固定。最后按稳定路径/ID 排序，每页 50，Revision 防止混合不同代数据。

结果列表将 `SelectedItem` 双向绑定到 HomeViewModel。当前选择只存在于内存；手动重查或索引 Revision 刷新前保存 `RangeId + FullPath`，新首屏仍含该身份时恢复对应新对象，否则清空。查询词、类别、范围、字段、通配符、正则或正文模式变化会先清空旧选择，防止操作区引用前一组条件。

`ISearchResultActions` 隔离 Windows Shell 与剪贴板。打开目标把完整路径直接交给默认关联程序；定位启动 `explorer.exe` 并把 `/select,<完整路径>` 作为单个 `ArgumentList` 项，避免命令字符串解释。驱动器根目录直接打开。ViewModel 在动作前重查文件或文件夹存在性，打开、定位及加入快捷入口对失效目标禁用并返回稳定提示；复制路径继续可用且只在用户主动点击时写入剪贴板。异常不含完整路径、堆栈或系统响应，最近使用记录只在成功提交打开请求后更新。

`ClearSearchCommand` 只在搜索文本非空时启用。执行后由 Query 的既有生命周期取消旧选择并启动空查询刷新，窗口在命令完成后的 Input 调度优先级把焦点还给 SearchBox。所选结果通过 `ShortcutStore.ContainsTarget` 派生“加入快捷入口/已在快捷入口”；任何快捷数据重载都会重新通知标签与命令，重复目标不进入写路径。

`ResetSearchContextCommand` 在存在查询、非全部类别或非全部范围时启用。它先取消旧查询，直接更新三个底层字段并只触发一次最终刷新，避免连续三次无效搜索。`SearchResultCountText` 和 `SelectedResultSummary` 与通用 Status 分离；结果替换、分页和搜索生命周期都统一刷新计数/序号。

## 4. 快捷入口

shortcuts.json schema 1 新增 group/pinned，旧数据默认空组/未固定。Load 先固定、再 order、再创建时间；Reorder 去重 ID，避免重复记录。管理窗支持 100 项测试、多选、分组、拖动和键盘排序、取消失效扫描。

`ShortcutManagerInteraction.Resolve` 根据当前筛选列表、选择 ID、扫描状态与撤销记录生成纯状态：多选只开放分组/固定/移除，单选才允许重新定位；上移/下移同时检查列表边界与 pinned 区边界；扫描时冻结数据变更并只开放取消。窗口在选择、筛选、分组文本、重载和扫描状态变化后统一应用该状态。Delete 与按钮共用批量预览，不直接删除引用或原目标。

批量移除预览对所选记录计算指纹，确认前再次核对，防止旧预览误删已修改记录。撤销保存在内存，合并时不覆盖同 ID 的新记录；原目标从不删除。当前引用和撤销记录所需图标都受孤立缓存清理保护。

## 5. 待办与通知

TodoDocument schema 4 在 schema 3 的 recurrenceAnchorAt、时区及 queuedOccurrenceAt 之上新增可空 `plannedStartAt`，升级前保存 `.pre-v4.bak`。时间块开始保存在 `plannedStartAt`，块结束复用 `dueAt`，让原排序和日期筛选继续工作；手动或单项 AI 修改截止时间时清除旧计划开始时间。主/额外提醒去重排序，最多 32 个额外时间；存储读取校验结构及规则，损坏可读为空但拒绝后续覆盖，保留原文件。

TodoStore.UpdateBatch 在同一存储锁内核对每项 `UpdatedAt`、验证全部候选，再一次原子写入；任一标识缺失、旧快照或规则错误使整批不写。RestoreBatch 使用确认后 `UpdatedAt` 防止撤销覆盖后续编辑，并以独立提示说明旧安排不能覆盖新内容。今日安排批量撤销只留在内存。

`TodoViewModel` 先从同一存储快照计算六筛选计数，再应用当前筛选、标题/备注页内查找和三种稳定排序。查询、排序与唯一选中项只存在进程内；刷新前保存 ID，刷新后仅恢复仍可见的同一事项。原生 `ListBox` 提供方向键/Home/End，代码层只在列表上下文解释 Enter/F2、`Ctrl+Enter` 和 Delete；单项写操作继续调用原命令与并发保护。

统一操作带绑定当前选择并在动作前按 ID 重读存储，避免旧行快照覆盖并发变化。完成/恢复、编辑、稍后、跳过、取消规则/提醒和删除按当前类型、完成状态、提醒与重复规则显示；卡片紧迫度与 AutomationProperties 名称不依赖颜色，选择摘要使用 polite live region。

手动编辑器的 `CanSaveEditor` 由编辑器可见、TodoStore 已装配和实时草稿有效性共同决定。标题/备注沿用 200/4000 上限，截止与提醒快捷动作只改草稿；日期、时间、提醒必填和基础重复字段即时解释，`TodoStore` 与重复/DST 校验仍是最终事实来源。字段变化清理旧提交错误、刷新命令与 live region。编辑器打开时捕获包含标题、备注、日期/时间、类型、通道、重复、时区、额外时间和仅此次的内存基线；字段变化通知未保存状态，取消只打开页内放弃确认。

手动及 AI 的单项写操作共用一个 `UndoRecord`：保存操作后的 `UpdatedAt`、写前快照与“预期不存在”删除标志。撤销前重读存储；时间戳不同、目标缺失或删除后重新出现均拒绝覆盖。快照只在进程内保留，后续操作覆盖上一条。

RecurrenceCalculator 用规则所属时区的日历钟点计算，每周以原锚点/星期一周界为基础，夏令时空档前移到首个有效分钟、重叠选后一次。无时区旧规则保持固定偏移。长期错过只汇总当前一次，下一时刻直接跳到未来。详细语义见[待办提醒设计](TODO_REMINDER_DESIGN.md)。

DeliverReminderIfCurrent 在存储锁内核对原到期时间、接受入队并推进对应规则，避免旧快照消耗并发改期后的新时间。notifications.json 独立保存排队、提交、处理、取消；同 TodoId/时刻去重。先持久化队列再推进待办，跨文件失败允许恢复时重试；不承诺跨进程崩溃的展示 exactly-once。

静默采用当前系统时区 HH:mm；提交最小间隔 30 秒，批量摘要并保留每项记录。普通待办不自动完成；最后一次独立提醒提交后完成，队列中尚未提交则保持待处理。Windows 通知显示未确认，无已读状态。记录最多 2,000；满额不丢弃排队事项，以失败反馈。清历史保留待处理提醒，队列随待办成组备份。

提醒中心从一次 `NotificationCenter.Snapshot()` 建立进程内行投影，先计算待处理/历史/全部计数，再应用标题查询、筛选和稳定排序；刷新前保存通知 ID，刷新后只恢复仍可见的同一记录。原生 `ListBox` 保留方向键/Home/End，代码层仅在列表上下文解释 Enter/F2、`Ctrl+Enter` 和 `Ctrl+Shift+Enter`。统一操作带绑定当前投影，并在执行详情、完成或稍后前复用通知中心与待办存储的既有目标校验；查询、筛选、排序、选择和摘要均不写入通知文件。

静默设置装配通知中心时捕获启用、开始、结束三个字段的已保存基线。编辑和夜间/午休/关闭预设只更新内存草稿；严格 `HH:mm` 校验及启用时起止不相同约束共同决定保存命令。成功写入后推进基线，失败保留草稿；清历史数量只统计已处理、已取消和已提交通道测试，继续保留排队/已提交业务提醒与业务待办。

`DailyJournalStore` 独立保存 `journal.json` schema 1：活动日期、最多 3,650 个唯一日期、4,000 字正文、单调 revision、更新时间、可空冻结时间和最多 256 条最小快照，总文件不超过 32 MiB。写入复用 `RecoverableAtomicFile` 的临时文件、原子替换和 `.previous`；结构或高版本损坏时读为空但阻止后续空写覆盖。历史编辑采用期望 revision，过期异步写入不能覆盖新内容。

当天视图从 TodoStore 一次快照按当前 Windows 时区匹配 `CompletedAt`、`PlannedStartAt`、`DueAt` 或 `ReminderAt`，只保留 ID、标题、当日完成/安排标志和相关时间，不复制备注、规则或通知。停止输入 500 ms 后在 `SemaphoreSlim` 串行路径自动保存，`Ctrl+S` 立即刷新；切日失败停留原日期。App 在启动、`TimeChanged` 和 Resume 调用日期刷新，旧活动日只冻结一次，后续待办变化不改历史快照。

Markdown 导出由用户打开系统保存对话框，建议 `YYYY-MM-DD.md`，格式固定为 UTF-8 无 BOM 与 LF。标题控制字符折叠为空格，正文只统一换行；目标必须为 `.md`，拒绝设备路径、ADS、链接目录和链接文件，再复用原子写入。导出目录不会获得搜索授权。删除接口只按日期修改 journal，不持有 TodoStore 写引用。复盘正文和快照不进入 AI、诊断、日志、搜索或遥测。

### 5.1 专注会话与低打扰协调

`FocusSessionStore` 独立保存 `focus-sessions.json` schema 1：单调 revision、最近有效时长、最多 10,000 条历史和可空活动 ID，总文件不超过 16 MiB。会话保存计划秒数、已累计秒数、开始/继续/结束时间、状态及可空 Todo ID，不保存标题或备注。写入沿用原子临时文件、替换、`.previous`、期望 revision 与损坏后写保护；运行和暂停合计最多一条。

`FocusSessionService` 将墙钟与进程内单调计时分离。运行中 UI 每秒取快照，只在开始、暂停、继续、提前结束、恢复校准、到时和退出检查点写盘。新进程按墙钟恢复；同进程取单调与墙钟增量较大者，墙钟回拨超过五分钟时自动暂停并要求用户继续。累计值截断到计划值，完成转换在持久化后发布且幂等。复盘投影按本地日期聚合 `Completed` 与 `EndedEarly`，Markdown 只输出次数和时长。

App 订阅同一会话快照并驱动三项独立效果：PetWindow 安静模式、宠物窗口点击穿透、托盘命令。安静模式保存用户原外观偏好，停止漫游计时器、随机气泡和鼠标朝向，拖动临时使用正面状态；正式提醒气泡不被屏蔽。结束时恢复设置，正常完成仅在系统允许动画时播放一次既有 jump。

`ForegroundFullscreenDetector` 只读取前台 HWND 的可见/最小化状态、DWM 扩展边界和监视器工作矩形，排除本进程；2 DIP 容差内覆盖桌宠所在监视器才判定真全屏。App 每 500 ms 采样并要求连续两次一致；分别保存用户手动隐藏和全屏抑制原因，只撤销自己造成的隐藏。`WindowClickThrough` 只增删 `WS_EX_TRANSPARENT` 位并保留其他扩展样式；打开设置、托盘恢复、结束专注和退出都会尝试清除。

角色卡由 App 为 manifest 中每个声明角色创建独立 `PetFrameCache`，只取 `idle/down/0` 冻结图片。HomeViewModel 在切换前核对角色 ID 与预览，再原子保存设置，成功后通过事件调用 PetWindow 的纯运行时切换；保存失败恢复原选择。启动时按已选角色、manifest preferred、首个可解码角色依次回退，所有候选失败则停止启动并提示重装资源。

## 6. AI

GET models 验证响应对象/data 数组/所选模型；最小生成验证独立主动确认，固定示例、max_tokens=256、只校验草稿不写入。普通草稿最多 1,024 output tokens；模型列表响应 2 MiB、草稿响应 256 KiB，UTF-8、25 秒请求与读取超时，取消独立传播。错误包含鉴权、权限、限流、未知模型、无效响应和网络/超时。

字段指纹绑定成功结果，编辑后旧结果不能保存。API Key 经 Windows 账户凭据存储，普通设置只保存引用。无 Key JSON 迁移保持 1 MB/100 项、重名跳过或重命名、新 ID、新引用、Untested 和不替换活动配置的兼容行为。

完整 AI 配置包使用 `.aipet-ai-config`。内层 schema 1 包含全部 profile 字段、Key、活动项、激活状态、Provider 启用状态、最多 32 个自定义 Provider、来源版本和 UTC 时间；不包含原设备凭据目标名。外层 schema 1 使用 PBKDF2-HMAC-SHA256 310,000 次、16 字节随机盐、AES-256-GCM 的 12 字节 nonce 和 16 字节 tag，格式标识作为附加认证数据。包最大 4 MB、最多 100 组配置，错误口令与篡改统一拒绝且不输出密文内容。

导入先完整解密校验并显示非敏感摘要。确认后为每组配置生成新 ID/凭据目标，依次写入 Key，再原子写 Provider 预设和 settings；失败时删除本次已写凭据并恢复预设，普通设置未提交。成功提交后才清理旧凭据并 ReloadAi，使导出时的活动配置立即进入当前连接。普通维护备份继续拒绝凭据字段，与用户主动创建的加密 AI 包是两种独立格式。

单项 AI 草稿只接收当前一句话、时间及时区。草稿支持重复和额外时间，确认时使用同一 TodoStore 规则校验。目标在本地按标题匹配，多目标可重新选择；确认后写入并保留一次内存撤销，不上传列表或索引。

今日安排是独立协议。ViewModel 只从用户明确勾选的 1～12 条待处理事项构造 ID、标题、备注、截止时间和 `UpdatedAt` 快照；未勾选且已有今天计划的事项会被合并为只含开始/结束的匿名 `occupiedBlocks`，不发送其标识、标题或备注。AI 必须原样覆盖全部选中 ID，返回当前偏移下今天未来的 15 分钟～4 小时时间块；额外/重复/缺失 ID、无绝对偏移、跨日、过去、新块互相重叠或与占用块冲突都直接拒绝。本地降级按截止时间排序，从严格晚于当前时间的下一刻钟开始分配 30 分钟块，并逐段跳过占用时间，不访问网络。两者都先形成内存草稿，逐项勾选确认后才批量写入。

## 7. 维护与恢复

备份格式 v2 保存文件 SHA-256，兼容 v1 读取。容量 512 MiB、单项 64 MiB、10,000 文件；拒绝路径越界/ADS/链接/未知模块、异常 JSON/schema、凭据字段。SQLite 是派生数据，不复制活跃数据库。模块包括设置、位置、待办/通知、每日复盘、专注会话、快捷项/图标、预设及实际 LocalAppData 日志。设置 schema 6 增加低打扰字段并在升级前保留 `.pre-v6.bak`；既有 `.pre-v4.bak`、`.pre-v5.bak` 规则保持。

QueueRestore 校验并复制待恢复包、记录哈希。用户确认退出，下次启动校验全部输入后保留每个模块 before 快照和 journal，再切换。失败整体 rollback；发现 applying 日志则启动恢复快照。恢复快捷项重写图标为当前根路径；恢复设置清除旧授权索引。旧待办备份不含通知时创建空队列，排队待办缺配套队列时拒绝。

缓存维护只删除无引用图标，并排队在下次启动重建 SQLite/sidecar 和日志。入口使用危险次要样式；独立决策窗口把“退出并重建”与默认“保留并返回”分开，并明确设置、待办、快捷入口、自定义引用图标和凭据不删除。RecoverableAtomicFile 使用唯一临时文件和 .previous，不覆盖不可解析的旧 JSON。诊断只输出白名单版本、计数和稳定状态，不含正文/路径/凭据。维护成功和失败共用独立 `MaintenanceStatus` live region；事件处理只映射预定义恢复提示，不把 `Exception.Message`、堆栈或目标路径传入视图。

交互卸载默认保留，明确清理才通过离线应用入口删除已知模块、维护快照、设置中记录的本应用 AI 凭据和固定 GitHub 更新令牌；静默保留。损坏/丢失配置中未记录的凭据或未知文件不擅自扩大清理范围。

## 8. 快捷唤出与每日备份

GlobalHotkeyGesture 只接受至少一个 Ctrl/Alt/Shift/Win 修饰键与一个受控普通键，规范化显示并拒绝重复组合。GlobalHotkeyService 创建消息窗口，通过 RegisterHotKey 接收 WM_HOTKEY；不使用低级键盘钩子。每次应用设置先释放原注册，任一新组合失败则释放本轮全部注册。应用退出统一 Dispose；桌宠和托盘入口不依赖全局注册。

默认组合为 `Ctrl+Alt+Space` 搜索和 `Ctrl+Alt+T` 快速待办。搜索入口显示宠物并按既有规则聚焦主页；快速待办选择待办页、执行新建命令并聚焦标题。两者继续调用 TrySelectTab，AI 设置存在未保存修改时仍走已有保留/放弃/取消流程。

全局快捷键和自动备份分别保存最后一次成功加载/写入的非敏感字段基线。计算属性驱动按钮的“有修改/已保存”标签和 CanExecute；规范化或持久化成功后才推进基线，校验与写入失败保持输入和 dirty 状态。

AutomaticBackupService 复用 DataMaintenanceService 的模块依赖、JSON/路径/凭据校验和备份格式 v2。正常启动读取设置后在后台执行；文件名保存 UTC 毫秒时间，24 小时内最多一次，成功后才按 1～30 份上限删除旧包。范围固定为设置、位置、待办/通知、每日复盘、专注会话、快捷项/图标及 Provider 预设，排除凭据、搜索索引和日志。校验、写入或保留清理失败时返回失败状态并保留旧包；卸载明确清理个人数据时删除 automatic-backups。

## 9. GitHub Release 在线更新

GitHubReleaseUpdateClient 固定读取 `mawenshui/windows-ai-desktop-pet` 的 latest stable Release，只接受三段稳定 SemVer、精确安装器文件名和 `SHA256SUMS.txt`。元数据/清单各限 1 MiB、安装器限 200 MiB；只接受无用户信息的 HTTPS，网络和读取均有独立超时。下载先写 `.download`，SHA-256 匹配后原子替换目标文件，失败删除临时文件且不改变当前安装。

HttpClient 默认使用 Windows 系统代理。元数据路由固定为 GitHub 官方 API、`gh-proxy.com` API 代理；安装器及清单路由固定为 `gh-proxy.com`、`ghfast.top`、`ghproxy.net` 和 GitHub 官方地址。单条线路在独立超时、响应或校验失败后继续下一条；结果只向界面暴露“GitHub 官方”或“智能加速线路”，不展示域名和代理术语。所有请求均匿名，不读取或发送旧版更新凭据。

客户端只接受精确 `v<SemVer>` 标签、固定仓库的 HTTPS Release 页面和 GitHub 返回的规范化 `browser_download_url`；资产大小必须在边界内。重定向只允许原请求主机及显式 GitHub 交付主机。若 Release 资产带 `sha256:` digest，必须为 64 位十六进制并与清单哈希一致；最终文件仍重新计算 SHA-256。任一不一致都会删除临时文件并阻止安装。

正常模式装配完成后调用 StartUpdateChecks，一次进程生命周期只启动一个初始检查。周期检查默认关闭，可设 1～168 小时；取消随应用退出。发现更新只显示版本和下载操作，不自动下载；后续失败或取消保留已发现版本，明确返回最新版本才清除。下载校验通过后 App 再次询问用户，用户确认且处理完未保存 AI 编辑后才以 `/SP-` 启动安装器并退出。preview/ui-e2e 不访问网络。

周期启用与间隔使用单独的已保存基线；无差异时禁用保存，校验或写入失败不推进基线。设置 schema 6 继续兼容读取 schema 5 的旧 `accelerationTemplate` 字段，但规范化后总是清空且业务从不读取；固定的旧更新凭据只保留原卸载清理路径，不再参与运行时请求。

## 10. 发布证据

collect-release-evidence 收集七组独立报告。release-evidence 绑定版本、提交、输入指纹、时间、环境以及烟雾/签名/硬件资产哈希；verify-release 拒绝 dirty、缺失/过期、FAIL/SKIP、缺项、错资产和错 SHA256SUMS。输入包含源码、测试、脚本、配置、素材、workflow、VERSION、Directory.Build.props 和离线手册。

Release workflow 在受保护的 self-hosted Windows runner 上发布已经通过验证的字节，下载后再比哈希。修改提交或构建输入必须重取证，既有历史成功不能迁移为当前 PASS。候选状态及限制见[当前状态](CURRENT_STATUS.md)。
