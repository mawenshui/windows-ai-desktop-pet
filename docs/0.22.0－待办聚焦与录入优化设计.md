## 1. 目标与边界

本轮继续优化已有待办能力，不新增页面、账号、云同步、遥测、外部资源、运行时依赖或 AI 数据范围。目标是让事项增多后的本地查找、排序、键盘浏览和常用操作保持紧凑可达，并降低手动填写日期、时间和长文本时的认知负担。

版本选择 `MINOR`：新增向后兼容的待办局部查找、排序、选中操作和快捷时间能力。设置 schema 维持 5，待办 schema 维持 4，快捷入口 schema 维持 1；查询、排序、选择、计数和校验提示均为进程内视图状态，不写入磁盘。

设计沿用 `.ui-craft/brief.md` 与 `.ui-craft/tokens.md`：桌宠仍是常驻主体，工具窗保持四页；继续使用奶油米白、柔和暖橙、原生 WPF 控件、非颜色状态、可见焦点和至少 36 DIP 的紧凑操作。签名细节是“聚焦操作带”：清单本身只表达事项与选中状态，当前事项的动作集中到列表下方，和主页搜索结果操作保持同一心智模型。

| 13 | UX-220-13 | 待办状态 | 增加非颜色紧迫度文本 | 至少区分已逾期、今天、未来、未安排和已完成；颜色只作辅助 |

| 15 | UX-220-15 | 手动录入 | 增加“今天 18:00”“明天 18:00”“清除截止”快捷动作 | 只更新编辑草稿并进入未保存状态，不直接写入待办文件 |
| 16 | UX-220-16 | 手动录入 | 增加“30 分钟后”“明天 09:00”“清除提醒”快捷动作 | 跨日时日期时间正确；提醒项清空后实时提示必须重新设置 |
| 17 | UX-220-17 | 手动录入 | 标题与备注显示长度计数并与存储上限一致 | 标题 200、备注 4000；输入控件使用同一上限，计数可由 UI Automation 读取 |
| 18 | UX-220-18 | 手动录入 | 增加实时编辑有效性提示 | 空标题、超长、缺少日期但填写时间、无效 `HH:mm`、提醒项无提醒时间时解释具体下一步；有效时明确可保存 |

顺序约束：先让数据投影支持查找和计数，再加入排序与选中，之后调整 XAML 操作结构，最后增加编辑快捷动作与实时校验。每个阶段先补 ViewModel 状态和自动化回归，再修改相应交互；任一阶段相关测试失败时不得把后续项目标记完成。

## 3. 状态与交互设计

### 3.1 查找、筛选与排序

待办查找是当前清单之上的本地视图过滤：先由选定日期筛选得到候选，再匹配标题或备注，最后按所选排序输出。六个筛选计数只由日期/状态规则计算，避免用户输入查询后每个标签同时变为零而失去方向感。查询不持久化、不进入诊断、备份说明或 AI 上下文。

排序使用页内短集合单选，不使用 Popup。时间最近沿用现有 `DueAt → ReminderAt → CreatedAt` 逻辑；新建在前按 `CreatedAt` 降序；标题按当前文化、不区分大小写排序，并以创建时间作为稳定次序。

### 3.2 选择与统一操作带

列表改为原生单选 `ListBox`，每个卡片只展示标题、状态、时间与简要备注。选中项下方出现暖橙浅色操作带，按钮按当前事项语义显示。刷新前保存选中 ID，刷新后只在结果仍可见时恢复；查找、筛选和排序不会把选择静默切换到其他事项。

键盘行为只在列表内生效：方向键、Home、End 使用 WPF 原生行为；Enter/F2 打开编辑器，Ctrl+Enter 执行完成或恢复，Delete 执行可撤销删除。编辑器内既有 `Ctrl+Enter` 保存优先，不与列表快捷键竞争。

### 3.3 录入与校验

快捷时间动作只修改草稿字段。截止快捷值为本地今天/明天 18:00；提醒快捷值为当前时刻向上取整后的 30 分钟后或明天 09:00。清除动作同时清空日期并保留默认时间文本，避免持久化半个时间值。

实时有效性提示是保存前指导，不替代 `TodoStore`、重复规则和 DST 校验。标题与备注长度直接沿用存储上限；日期未选时对应时间文本不构成待保存值，但无效格式仍提示用户先修正。提醒项必须有有效提醒日期时间。提交失败保留草稿，任一字段变动后撤下旧提交错误并重新计算提示。

## 4. 测试计划

1. `TodoViewModelTests` 覆盖查找、清空、查询空态、六筛选计数、三排序、选择恢复/清除、摘要和操作可用性。
2. `TodoViewModelTests` 覆盖今天/明天/清除截止、30 分钟后/明天/清除提醒、跨日、长度计数和实时有效性。
3. WPF 生命周期测试覆盖 `Ctrl+F` 焦点、ListBox 选中、Enter/F2/Ctrl+Enter/Delete、操作带绑定与编辑器快捷键优先级。
4. XAML 合同测试覆盖原生 ListBox、单一操作带、36 DIP、MaxLength、非颜色紧迫度、动态摘要和 AutomationProperties 名称。
5. 完成实现后运行两次 `scripts/test.ps1 -CI`，再运行独立 UI、系统、性能和打包/烟雾入口；无法提供的签名或物理环境证据如实记为 FAIL/SKIP。

## 5. 验收标准

| ID | 验收要求 |
| :--- | :--- |
| AC-UX-220-01 | 待办查找只在本地匹配标题/备注；`Ctrl+F` 聚焦，清空保留日期筛选和排序 |
| AC-UX-220-02 | 查询无匹配、筛选为空和存储为空三类状态给出各自唯一主操作，操作后用户可继续任务 |
| AC-UX-220-03 | 六筛选计数与同一存储快照一致；三种排序稳定且不更改持久化数据 |
| AC-UX-220-04 | 列表原生键盘移动可用；刷新只恢复仍可见的同一 ID，不自动选中另一项 |
| AC-UX-220-05 | 统一操作带仅对当前事项生效，所有既有动作语义、通知处理和最近撤销不回归 |
| AC-UX-220-06 | Enter/F2、Ctrl+Enter 和 Delete 只在列表上下文生效；编辑器 `Ctrl+Enter` 仍优先保存 |
| AC-UX-220-07 | 已逾期、今天、未来、未安排和已完成不只靠颜色表达，待办项与操作均有目标化可访问名称 |
| AC-UX-220-08 | 截止与提醒快捷动作只修改草稿；跨日和清除结果正确，未确认前文件不变 |
| AC-UX-220-09 | 标题/备注计数与 200/4000 存储上限一致；实时提示覆盖空标题、时间格式和提醒项必填 |
| AC-UX-220-10 | 修正任一字段后旧错误消失、保存命令状态与 live region 同步；最终领域校验失败仍保留全部输入 |

## 6. 非目标与发布边界

- 不新增跨待办全文索引、标签、优先级、批量删除或跨重启选择记忆。
- 不把待办查询、排序、选择、字符计数或实时校验写入配置文件。
- 不扩大 AI 输入；待办页局部查询和未选事项正文不进入任何 AI 请求。
- 不以进程内 WPF 测试替代真实前台输入、多屏/缩放、休眠/时区、Explorer 重启或代码签名。
- 完整门禁未通过时只能作为候选，不创建稳定标签或 GitHub Release。
