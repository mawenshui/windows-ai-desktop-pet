# 成熟桌宠产品调研与功能机会

| 属性 | 内容 |
| :--- | :--- |
| 文档状态 | 市场调研与机会建议，不是 PRD、RFC、版本承诺或已实现声明 |
| 调研日期 | 2026-09-17 |
| 当前项目基线 | 0.24.0 正式版 |
| 核心样本 | VPet-Simulator、Bongo Cat、Desktop Mate、Spirit City: Lofi Sessions、Shimeji-ee |
| 补充样本 | Weyrdlets 2.0；仅用于交叉验证“桌宠 + 生产力”方向，成熟度证据弱于核心样本 |
| 目标 | 找出已经被市场产品验证、当前项目尚未实现、且符合本地优先与低打扰定位的功能 |

## 1. 结论

当前项目的工具能力已经明显强于多数传统桌宠：本地搜索、快捷入口、待办、重复提醒、今日安排、每日复盘、备份恢复、更新和 AI 结构化录入均已形成完整链路。真正的短板不是再增加一个工具页，而是以下三类连接不足：

1. **工具行为与桌宠表现没有形成反馈闭环。** 用户完成工作、进入专注或休息时，宠物没有对应的持续状态、动作和正向反馈。
2. **桌宠个性与内容扩展不足。** 当前只有四个内置 RGS 角色，外部 2D 角色包仍停留在隔离原型，用户无法安全导入、管理和切换自己的角色。
3. **“常驻但不打扰”的控制仍不完整。** 已有显示/隐藏、置顶、漫游和托盘，但没有自动全屏避让、临时点击穿透、演示模式或按场景恢复。

综合市场重复信号、当前架构复用程度、隐私风险和实现成本，建议顺序为：

1. **优先候选：专注会话 + 宠物状态、低打扰模式、安全 2D 角色包库。**
2. **第二梯队：隐私友好的工作活动反应、习惯追踪、只增不减的轻量成长。**
3. **长期方向：窗口边缘停留、多宠互动、无代码动作编辑器、环境音和小游戏。**

不建议近期照搬通用 AI 陪聊、屏幕持续识别、可执行代码插件、3D/VRM、云端多人、交易市场或付费角色商城。它们在部分产品中存在，但与当前项目的隐私、安全、资源和许可边界冲突较大，且“有产品在做”不等于已经证明适合本项目。

## 2. 调研方法与判断口径

### 2.1 成熟度口径

核心样本至少满足以下两项：

- 已公开运行约一年或拥有更长的持续维护谱系；
- 有显著的商店评价量、活跃用户或创作者生态；
- 有持续更新、公开仓库、官方文档或创意工坊；
- 功能不是只存在于概念页、预告或一次性演示。

Steam 评价数量和好评率只用于判断产品是否被大量真实用户长期使用，不用于证明每一项功能都优秀。评价数字会持续变化，本文只记录 2026-09-17 的页面快照。

### 2.2 “好用”的筛选标准

入选功能需同时满足：

- 至少在一个成熟样本中是核心能力，或在多个产品中重复出现；
- 能缩短当前项目已有任务的路径，或显著增强陪伴感；
- 可以设计成默认本地、可关闭、可解释、可恢复；
- 不依赖商业 IP、侵入式监控、账号体系或不受控脚本执行；
- 当前项目文档和正式产品入口能够确认尚未实现。

### 2.3 当前项目核对范围

项目现状以[当前状态](CURRENT_STATUS.md)、[PRD](Windows桌面宠物产品需求文档_PRD.md)、[工程规范](PROJECT_SPEC.md)和[用户手册](USER_MANUAL.md)为准，并对 `src/`、`tests/` 做了关键词核对。

已确认的相关边界：

- 已有四个内置 RGS 2D 角色、漫游、气泡动画、鼠标朝向跟随和基础点击/拖动。
- 已有待办、提醒、今日安排和每日复盘，但没有专注计时、习惯打卡、连续记录或宠物成长。
- 已有托盘显示/隐藏与置顶设置，但没有自动全屏避让、临时点击穿透或演示模式。
- 外部 2D 角色包只有隔离原型，没有正式导入、预览、启用和回退入口，见[原型评估](EXTENSION_PROTOTYPE_REPORT.md)。
- 通用聊天、插件执行、3D、云同步、商城、账号和遥测明确未接入。

## 3. 市场样本

### 3.1 VPet-Simulator

**成熟度证据：** 2023 年发布；Steam 全语言页面约 5.1 万条评价且总体“好评如潮”；开源并长期维护；支持 Steam 创意工坊和 ModMaker。来源：[Steam 商店](https://store.steampowered.com/app/1920960/VPet/)、[官方仓库说明](https://github.com/LorisYounger/VPet/blob/main/README.md)。

**已验证做法：**

- 摸头、提起、爬墙、喂食等大量持续互动和动画。
- 体力、饱腹、口渴、心情、健康、好感和经验等养成状态。
- 创意工坊可扩展角色动画、物品、食物饮料、工作、对话和主题。
- 开放代码插件能力，社区可以增加闹钟、仪表盘等功能。

**对本项目的启示：** “角色内容生态”和“互动后有可见反馈”是长期留存的重要来源；但可执行代码插件和复杂生存数值不应直接照搬。

### 3.2 Bongo Cat

**成熟度证据：** 2025 年发布；Steam 英文评价约 2.9 万条、约 96% 好评，近期仍有大量评价和活跃用户。来源：[Steam 商店](https://store.steampowered.com/app/3419430/Bongo_Cat/)、[Steam 社区](https://steamcommunity.com/app/3419430)。

**已验证做法：**

- 用户键盘或鼠标活动会立即触发宠物动作，工作本身成为互动。
- 极低学习成本：输入、积累、获得外观物品，不需要切到复杂主界面。
- 帽子、皮肤、成就和多人同屏形成轻量收集与展示循环。
- 官方更新持续修复多屏、缩放、透明、全屏游戏抢焦点等桌面常驻问题。

**对本项目的启示：** 最有价值的不是物品交易，而是“用户工作时宠物也在陪同反应”的即时性；实现时必须避免记录具体按键、窗口标题或输入内容。

### 3.3 Desktop Mate

**成熟度证据：** 2025 年发布；Steam 全语言评价约 9,000 条；2026 年仍持续发布版本和角色更新。整体评价褒贬不一，说明其覆盖面和活跃度高，但商业化与体验并非都值得复制。来源：[Steam 商店](https://store.steampowered.com/app/3301060/Desktop_Mate/)、[官方 Steam 社区与更新](https://steamcommunity.com/app/3301060/)。

**已验证做法：**

- 角色坐在真实应用窗口边缘，在窗口之间跳跃并与鼠标光标互动。
- 摸头、报时和内置闹钟把陪伴动作与轻工具结合。
- 部分角色组合可触发双角色联动动作。
- 官方持续处理跨显示器缩放、动作时机和常驻稳定性。

**对本项目的启示：** 窗口边缘是比“只在屏幕底部走动”更有空间感的舞台；但窗口枚举、DPI、多屏和前台应用兼容成本很高，适合独立 RFC 和原型，不适合顺手加入。

### 3.4 Spirit City: Lofi Sessions

**成熟度证据：** 2024 年发布；Steam 全语言评价超过 1.4 万条且约 97% 好评，2026 年仍计划持续更新。它不是透明悬浮式传统桌宠，但“陪伴角色 + 生产力”的产品定位与本项目高度邻接。来源：[Steam 商店](https://store.steampowered.com/app/2113850/Spirit_City_Lofi_Sessions/)。

**已验证做法：**

- 待办、专注会话计时、习惯追踪和日记形成完整日常工作流。
- 工作和习惯行为获得 XP，解锁角色、房间外观与精灵线索。
- 环境音、音乐和场景变化用于建立低压力的工作氛围。
- 收集与装饰是生产力行为的正向反馈，而不是失败惩罚。

**对本项目的启示：** 当前项目已经有待办和复盘，补上“专注会话”和轻量习惯后，可以低成本形成相似闭环；不需要复制完整 3D 房间或音乐平台。

### 3.5 Shimeji-ee

**成熟度证据：** 产品谱系可追溯至 2009 年，持续出现维护分支和跨平台适配；当前维护分支仍处理 DPI、现代 JDK、窗口识别和行为配置。来源：[维护分支说明](https://github.com/DalekCraft2/Shimeji-Desktop/blob/main/README.md)、[版本演进记录](https://github.com/DalekCraft2/Shimeji-Desktop/blob/main/kilkakon.txt)。

**已验证做法：**

- 角色图片、动作和行为通过资源目录与 XML 配置，可替换和分享。
- 支持同时运行多种角色、克隆、角色间动作和按角色控制。
- 角色可在屏幕、任务栏和应用窗口边缘行走、攀爬或停留。
- 对多屏、DPI、透明度、暂停、快速隐藏和窗口黑名单做了长期迭代。

**对本项目的启示：** 长寿的核心不是功能堆叠，而是开放角色资源和可组合行为；同时，官方说明也提示角色过多会增加启动时间和内存，必须设置数量与资源预算。

### 3.6 Weyrdlets 2.0（补充样本）

**证据边界：** 2024 年首发并在 2026 年进入 2.0 阶段；当前商店评价样本较少，因此不作为核心成熟度证据，只用于验证多产品重复出现的功能。来源：[Steam 商店](https://store.steampowered.com/app/2366060/Weyrdlets/)、[桌面模式说明](https://weyrdlets.wiki.gg/wiki/Desktop)。

**已验证做法：**

- 桌面模式可喂食、玩玩具、抚摸、移动宠物和启动小游戏。
- 番茄计时、健康记录和待办可以在游戏内与桌面模式使用。
- 角色、住所、饰品、贴纸、种植、采集和小游戏形成成长循环。

**对本项目的启示：** “生产力工具触发宠物反馈”再次出现，但完整家园、社交和采集系统会显著扩大产品范围，不应作为近期目标。

## 4. 市场反复出现的有效模式

| 模式 | 市场证据 | 对当前项目的意义 |
| :--- | :--- | :--- |
| 工作行为直接变成宠物动作 | Bongo Cat、Spirit City、Weyrdlets | 让用户不必专门“玩宠物”，工作时自然获得陪伴反馈 |
| 常驻但可以立刻让路 | Desktop Mate 的低打扰定位、Bongo Cat 的全屏兼容修复、Shimeji 的暂停/快速隐藏 | 当前显示/隐藏能力应升级为可恢复的场景模式 |
| 角色内容可替换、可分享 | VPet 创意工坊、Shimeji 图片集和行为配置 | 当前 EXT-08 原型有明确产品化价值 |
| 正向进度增强留存 | Spirit City 的 XP/解锁、Bongo Cat 的外观收集、VPet 的好感/经验 | 可把现有待办、专注和复盘结果转为非惩罚性成长反馈 |
| 空间互动提升“住在桌面上”的感觉 | Desktop Mate、Shimeji | 窗口边缘停留比增加更多菜单更能提升桌宠感 |
| 创作者工具扩大内容寿命 | VPet ModMaker、Shimeji 配置生态 | 应先做安全角色包，再考虑无代码行为编辑器；不可直接开放任意代码 |

## 6. 优先候选的最小产品定义

### 6.1 专注会话 + 宠物状态

建议把它放在现有待办页，而不是新增第五个主页面：

1. 用户可从一个待处理事项启动 15～120 分钟专注会话，也可启动不关联事项的会话。
2. 专注时宠物进入读书、打字、陪坐等低运动状态；休息时恢复伸展、散步或庆祝动作。
3. 会话到期只提醒和记录，不自动完成待办；完成仍由用户明确确认。
4. 会话结果只保存开始、结束、计划时长、实际时长和可选待办 ID，不记录前台应用、窗口标题或输入内容。
5. 每日复盘可显示“专注次数/时长”，但不会自动生成 AI 总结，也不会把记录发送给 Provider。
6. 退出、休眠和改时后按已有提醒规则恢复或汇总，不承诺进程外准点。

它同时补足工具价值与宠物表现，是最契合现有架构的新增功能。

### 6.2 低打扰模式

建议提供三个互斥模式，并始终可从托盘恢复：

| 模式 | 行为 |
| :--- | :--- |
| 正常 | 保持当前点击、拖动、漫游和置顶行为 |
| 专注 | 宠物降为静止/低动作；可选点击穿透；工具窗和全局快捷键仍可用 |
| 演示 | 当前显示器进入全屏应用、投屏或用户手动开启时隐藏宠物与气泡，退出后恢复之前状态 |

关键边界：

- 自动隐藏和用户手动隐藏是两种状态，不能互相覆盖；全屏结束后只恢复自动隐藏前可见的宠物。
- 点击穿透必须有托盘和快捷键兜底，不能让用户失去控制入口。
- 不读取窗口正文、截图或输入；只使用可见顶层窗口边界和全屏状态。
- 多显示器按屏幕分别判断，不能因为副屏视频全屏而无条件隐藏主屏宠物。

### 6.3 安全 2D 角色包库

优先把现有 EXT-08 原型产品化，而不是直接接入在线市场：

1. 用户从本地目录或 ZIP 选择角色包，先预览名称、作者、许可、帧数、体积、动作与来源指纹。
2. 只允许声明式 `pet.json`、PNG 和 `SOURCE.txt`；禁止 DLL、脚本、网络地址、绝对路径、重解析点和包内可执行文件。
3. 继续执行 SPDX 白名单、路径越界、帧尺寸、总解码内存和文件数量限制。
4. 导入到隔离目录前后复核指纹；复制失败不产生半导入状态。
5. 角色库支持启用、预览、禁用、移除和损坏回退，内置 RGS 角色永远保留为安全回退。
6. 首版不提供在线下载、付费、评分、自动更新、3D 或代码行为扩展。

这项能力已经有安全原型和测试基础，市场又反复证明自定义角色是桌宠长期价值的主要来源。

### 6.4 隐私友好的工作活动反应

建议借鉴 Bongo Cat 的即时反馈，但不要复制其输入采集模型：

- 默认关闭，由用户明确开启。
- 首版只通过 Windows 的最近输入时间识别“活跃/空闲/恢复”，不注册全局键盘内容记录，不保存键码、点击位置、窗口标题、进程名或输入频率明细。
- 活跃时可播放敲键、陪坐、观察等动画；持续空闲后进入休息；恢复时打招呼。
- 统计只保留可选的分钟级活跃区间或完全不落盘，并提供“立即清除”。
- 不请求管理员权限，不为提高游戏内输入识别率绕过其他程序的权限边界。

这样保留“宠物和用户同步工作”的价值，同时降低隐私、杀毒误报和信任成本。

## 7. 第二梯队与长期方向

### 7.1 习惯追踪

在待办重复规则之上增加“习惯”类型：按日/周设目标次数，手动打卡，显示近 7/30 天完成情况。打卡可触发宠物庆祝，但漏打不让宠物生病、不发送催促轰炸，也不自动修改待办。习惯数据继续本地保存并纳入备份、恢复和复盘。

### 7.2 轻量成长

推荐只做正向累积：完成专注、待办或复盘获得“亲密度”，解锁内置动作、气泡样式或合法的内置装饰。不得设置离线衰减、饥饿死亡、连续登录奖励、随机付费箱或可交易物品。用户应能关闭成长系统，并可在维护页重置。

### 7.3 窗口边缘互动

只允许宠物读取公开可见的顶层窗口矩形，把它们当作临时平台；不得移动、缩放、关闭或注入其他应用窗口。首个原型应只支持当前显示器、普通非全屏窗口和明确黑名单，并对管理员窗口、锁屏、UAC、安全桌面和未知边界直接回退到屏幕底部。

### 7.4 多宠互动

首版最多同时显示 2 个角色，只支持错身、打招呼、并排休息等无碰撞破坏的组合动作。需要明确 CPU、内存、帧缓存和窗口数量预算；超过预算时降低帧率或回退单宠，而不是无限克隆。

### 7.5 创作者工具

角色包稳定后再考虑精灵表切分、动作预览和声明式状态图。编辑器输出必须仍是受限资源包，不能生成或执行 C#、PowerShell、JavaScript、DLL 或任意网络请求。VPet 的代码插件能力适合开放生态，但不符合本项目当前安全边界。

### 7.6 环境音与小游戏

环境音仅考虑 CC0、自有或用户本地文件，默认静音并跟随专注会话；不得抓取第三方流媒体或捆绑来源不明音乐。小游戏应限制为一分钟内可结束、不会抢焦点的互动，不建设完整家园、货币、商城或广告体系。

## 9. 建议实施顺序

### 阶段一：提升每日可用性

1. 为“专注会话”和“低打扰模式”建立独立 PRD/RFC、隐私说明和验收编号。
2. 先实现托盘可恢复的模式状态与全屏检测，再接入专注计时。
3. 把专注状态映射到现有宠物动画，结果投影到每日复盘，不扩展 AI 数据范围。

### 阶段二：提升个性与留存

1. 复核 EXT-08 原型限制，把角色包预览、导入、启用、移除和回退迁入正式模块。
2. 在角色包稳定后增加隐私友好的活跃/空闲反应。
3. 通过用户测试决定是否加入习惯与正向成长；先验证价值，再设计奖励内容。

### 阶段三：建立创作者生态

1. 独立验证窗口边缘、多宠的多屏/DPI/资源预算。
2. 冻结声明式行为 schema，再做无代码编辑器。
3. 在线分享、市场、3D、插件和云功能继续保持在范围外，除非分别通过安全、隐私、许可和运维门禁。

## 10. 建议优先验证的问题

在进入实现前，建议用 8～12 名真实用户完成以下验证：

- 专注计时是用户愿意从桌宠启动，还是已经被现有计时器覆盖？
- 宠物在专注时应更安静还是更频繁反馈？
- 自动全屏隐藏、点击穿透、手动隐藏三者的默认值是什么？
- 用户更想导入自己的角色，还是先要更多内置合法角色？
- “活跃/空闲反应”是否会被误解为键盘记录？哪种说明和状态指示能建立信任？
- 成长反馈更适合动作、气泡、外观还是数值？用户是否希望完全关闭？

成功指标应优先看任务完成率、功能留存、误触/打扰次数和资源占用，而不是单纯统计在线时长或点击数。
